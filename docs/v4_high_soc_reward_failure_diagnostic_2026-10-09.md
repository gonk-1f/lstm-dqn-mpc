# V4 高 SOC 决策、奖励反馈与长期失败传播专项诊断（P1）

依据 [P0 审计](v4_fc_runtime_feasibility_audit_2026-10-09.md)及两组已归档的 40 轮实验：[原均匀采样](results/v4_scale001_beta500_replay32_target500_seed42_40r_20261008_220104/raw/report.json)、[失败终止配额 2](results/v4_scale001_beta500_replay32_target500_quota2_seed42_40r_20261009/raw/report.json)。下文轨迹行号是相应样本的 ONBOARD transition 从 0 起的序号，**不是原始数据行号**。只读取归档和 Train 数据，用正式区间模型复算了两个单步状态；未训练、未打开 Test，未改算法、参数或经济账本。配额 2 实验第 40 轮 Train 为 25/30；当前没有合格 checkpoint，两个归档也均未保存逐轮网络权重，因此无法恢复轨迹当时每个实际状态的 61 个 Q 值。

## A. 源码已确认的机制

1. [动作网格及掩码](../src/v4/control.py#L185-L202)每 30 s 在 `0,10,…,600 kW` 中筛选，同时检查 `P_bat=L-P_FC∈[-624,1248] kW` 和正式充放电效率递推后的 `SOC_next∈[0.2,0.8]`。掩码只保证这一控制步；[贪婪选择](../src/v4/dqn.py#L139-L156)在可行动作中取在线经济 Q 最大值，辅助 outcome 网络不参与选择。0 kW 在当前[正式区间模型](../src/v3/control.py#L134-L166)里视为 FC OFF；前一正功率到 0 有变载费用，随后 0 到正功率又有一次完整启动费用。没有独立待机状态。
2. [SOC 软惩罚](../src/v4/control.py#L24-L32)为 `500 × distance(SOC_next,[0.4,0.6])²`，只在 ONBOARD 步加入 reward；`SOC≈0.8` 时约为 20 元/步。高 SOC 下放电会略降此项，保持或继续充电不会。它既不能使零负载时凭空消耗电能，也不是 FC 启停惩罚。
3. [电量反馈](../src/v4/reward_feedback.py#L10-L29)定义 `B(s)=K(0.6-s)`，`K=c_shore E_bat/η_chg=1.10×624/0.95≈722.53 元/SOC`。每个 ONBOARD 步的训练奖励加 `−[B(s_next)-B(s_before)]`；每个正常段末步再加 `B(s_T)-B(s_0)`。岸电结算先计入旧奖励，校正使用**岸充前**的 `s_T`，多个 ONBOARD 段分别计。岸电本身没有 DQN 动作或 SOC 软惩罚；真实岸充与 modeled terminal settlement 没有改动。对[失败后缀](../src/v4/failure_replay.py#L58-L90)，最后一个已执行动作标为失败终止，按该段初末 SOC 做相同校正，再**仅一次**加入 10132.6601 元等价失败惩罚；失败惩罚不进入真实经济账本。
4. 当前 [n=1 TD 目标](../src/v4/dqn.py#L23-L43)为 `y=r+γ(1-done)Q_target(s',argmax_{a∈mask}Q_online(s',a))`。失败终止 `done=True`、空后继掩码，不 bootstrap；前一动作仍只通过下一状态 Q 间接受其影响。配额 2 的[采样器](../src/v4/dqn.py#L399-L409)每个 64 条 batch 优先抽两条**真正带失败惩罚的终止经验**，其余为普通经验；失败段非终止前缀虽进入经济 replay，并不属于终止配额。辅助 [outcome 监督](../src/v4/dqn.py#L287-L331)将失败段所有已执行动作标成观测失败，并用二分类损失训练独立网络；此标签是整条行为轨迹的关联结果，不是每个早期动作的反事实因果判定。

## B. 已由轨迹与正式模型验证的现象

### B1. 被迫 0 kW 与主动 0 kW 是两类事件

对[配额 2 实验第 40 轮 greedy Train 轨迹](results/v4_scale001_beta500_replay32_target500_quota2_seed42_40r_20261009/raw/round_040_train_trajectories.json.gz)的 30 个样本、15119 个已执行 ONBOARD 步，按正式 SOC 公式及动作网格重建**当前**掩码（归档字段 `next_feasible_actions_kw` 属于下一状态，不能拿来判断当前动作）：

| `SOC_before≥0.79` 且 `FC=0` | 步数 | 原因与直接证据 |
| --- | ---: | --- |
| 无正功率网格动作，被迫选 0 | **2372** | 其中负载严格为 0 的 2057 步、`0<L<10` 的 315 步。全部 2372 步中，10 kW **电池功率约束允许**，但会让 `SOC_next>0.8`；连续正功率允许上界为约 `0.025–9.986 kW`，均落在首个 10 kW 网格点以下。故这是 **SOC 上限与 10 kW 离散化共同造成的网格不可行**，不是电池充放电功率不足，也不是 DQN 主动停机。2057 个零负载步，即使取 0 kW 也没有电池放电通道。 |
| 有正功率可行，策略主动选 0 | **235** | 全部负载至少 10 kW；232 步前一 FC 为正且存在距离负载 ≤10 kW 的正功率可行动作。229 步在同一 ONBOARD 段的下一步重新启动；其中 226 步是“正→0→正”。这些是需要分析 Q 排序与延后启动费用的片段。 |

P0 的 326 次启动中 264 次属于 ONBOARD 内部重启。上述 229 是其中**高 SOC 且前一步选 0 后紧接重启**的子集，不能把两种计数直接等同；另有 24 次高 SOC 的紧接重启，其停机步是掩码被迫 0。连续运行规则若没有设备待机与最小出力依据，不能据此全局禁止 0 kW。

**被迫停机例**：`zero_boundary_022`、voyage 0、transition 181：`SOC_before=0.79995943`、负载 4.170 kW、前 FC 10 kW，当前网格掩码只有 `{0}`。正式区间模型复算，选 0 后 `SOC_next=0.79990081`；假设选 10 则为 `0.80003339`，违反硬上限。后者仅用于解释掩码，**不是合法控制反事实**。

**主动停机例及合法单步反事实**：`zero_boundary_002`、voyage 0、transition 33：`SOC_before=0.79990011`、负载 154.864 kW、前 FC 100 kW；掩码为 `{0,10,…,160}`。实际选择 0，下一步又选 350。将此前 33 步的归档动作在[正式经济区间模型](../src/v3/control.py#L134-L166)复算后，SOC 与每步归档吻合；在**同一物理状态**下比较实际 0 和合法 150 kW：

| 单步量 | 实际 FC 0 | 反事实 FC 150 |
| --- | ---: | ---: |
| Battery kW；`SOC_next` | 154.864；0.79772309 | 4.864；0.79983173 |
| H₂ 元 | 0 | 1.3237 |
| FC 低载/高载/变载/启动退化 元 | 0/0/**11.025**/0 | **1.2713**/0/**5.5125**/0 |
| Battery 退化 元 | 0.2162 | 0.0061 |
| SOC 软惩罚 元；即时电量反馈 元 | 19.5472；−1.5730 | 19.9664；−0.0494 |
| **含软惩罚的原单步 reward 元** | **−30.7884** | **−28.0800** |
| **重分配后该步 reward 元** | **−32.3613** | **−28.1294** |

该步 150 kW 的即时训练 reward 比 0 kW 高约 4.23 元，但归档动作仍为 0。**不能据此证明程序选错 Q 最大值**：DQN 比较的是折扣后续回报的 Q，不是即时 reward。归档没有该状态的网络权重或逐动作 Q；反事实也只复算了当前步，没有沿新动作重跑未来轨迹。实际 0→正功率的**下一步**会收取启动分项，当前单步表没有提前虚构它。

### B2. SOC 惩罚、重分配与高 SOC 驻留

第 40 轮 greedy Train 已执行步中，`SOC_before≥0.79` 为 11769/15119 步；其间 Battery 放电 5009 步、充电 4703 步、功率为 0 的 2057 步。`SOC_after≥0.79` 的 11794 步产生软惩罚合计约 234654 元、平均 19.896 元/步；这是**训练软惩罚，不是实际经济费用**。全体已执行步软惩罚合计约 254664 元，不能与仅完成航段的真实成本混算。高 SOC 持续存在是轨迹现象，不能仅据此断言惩罚符号错误：零负载步无法主动放电；有负载时则需要比较具体可行动作及后续 Q。

逐段核对 62 个已执行 ONBOARD 段（含失败样本中已完成的前段及当前失败后缀），`Σ即时电量反馈+末步校正` 的绝对残差均小于 `10⁻⁶` 元。正常段 `Σr_new=Σr_old`；失败段 `Σr_new=Σr_old−C_fail`，例如 `_015` 失败段 `−4956.15−10132.66=−15088.81` 元、即时反馈 `−288.97` 与失败末步校正 `+288.97` 抵消。`_017` 前面已完成的段没有被后段失败的校正跨段抵消。就检查的代码和归档而言，**未发现**软惩罚符号颠倒、电量反馈重复计入、岸电重复计价或失败末端遗漏校正的确定错误。若样本在岸电后再航行，源码是以每个 `voyage_initial_soc` 单独结算；本次归档逐段恒等式也覆盖了多段样本。

### B3. 三个反复失败航段：早期分配与末端行为

第 40 轮三段都因下一步 SOC 下限导致空掩码；P0 已在**同一正式环境**给出完整可行序列，因此不是总额定功率结构性不可行。下表只统计失败所在 ONBOARD 段，不跨岸电；`前/末`是该段前或末 N 个已执行步，负载和 FC 为平均 kW：

| Train 样本；失败时本段长度 | 前 32 步：负载/FC；SOC | 末 32 步：负载/FC；SOC | 末 8 步 FC 选择与余量 |
| --- | --- | --- | --- |
| `_015`；151 步 | 162.6/585.6；0.6000→0.7717 | 1096.4/105.0；0.6460→0.2001 | 最后 7 步连续选 40，负载约 1091–1097；这 7 步 **600 kW 仍可行**。末步才选 440，下一未执行负载 1085.65 kW 时无可行动作。 |
| `_017`；44 步，第 3 个 ONBOARD 段 | 727.4/180.6；0.5756→0.3292 | 786.4/127.8；0.4975→0.2012 | 末 7 步选 40，负载约 799–840，**600 kW 仍可行**；末步才选 440，下一未执行负载 861.80 kW 时失败。 |
| `_044`；219 步 | 185.5/590.0；0.6000→0.7642 | 740.4/114.7；0.4831→0.2012 | 末 7 步选 40，负载约 787–829，**600 kW 仍可行**；末步才选 270，下一未执行负载 832.41 kW 时失败。 |

因此不能把这三段说成“从出港起一直低 FC”：`_015` 与 `_044` 前期几乎满功率充电，随后进入高 SOC 区域并转向电池供电，低 SOC/高负载时又连续选择低功率。尤其 `_017` 的失败在岸电后的新段，必须以该段起始 `SOC=0.5756` 分析，不可沿用全样本最初 SOC。末 8 步中所有被指出的 40 kW 选择都是**策略选择**，不是高 SOC 掩码强制 0 的问题；当时可选 600 kW。具体为何 Q 仍排 40 更高，现有归档不足以证实。

### B4. n=1 失败信号与已归档 Q 诊断

失败惩罚只落在最后一个**已经执行**的 transition；失败负载行没有虚构动作。三段失败末 8/32/100 步的原奖励、即时电量反馈与软惩罚均已分别核算，见上面的 SOC 轨迹；例如 `_015` 末 8 步原奖励和为 −202.48 元，即时电量反馈和为 −81.59 元，软惩罚和为 98.08 元，最后一条另外承受 −10132.66 元等价惩罚。n=1 使末前第 8、32、100 步都**没有直接包含**这笔惩罚，只能靠多次有序 TD bootstrap 逐步传播；经验回放随机抽样顺序和函数逼近不保证在 40 轮内传播到位。

| 第 40 轮训练统计，奖励缩放单位 `×0.001` | 均匀采样 | 失败终止配额 2 |
| --- | ---: | ---: |
| greedy Train 完成 | 12/30 | 25/30 |
| 失败终止 TD 采样数 / 本轮总采样位置 | 31/21568 | 942/30144 |
| 失败终止 TD MAE | 9.5607 | 1.3816 |
| 总体 TD MAE | 0.0286 | 0.1287 |

配额确实改善了**终止样本本身**的拟合；总体 TD MAE 反而较高，并不能据此判定训练数值发散。完成率同时提高，但两次训练的轨迹和经验池随策略演化不同，不能仅凭两组终值证明配额已经把惩罚传到失败前 8/32/100 步。归档有[固定合成状态 Q 诊断](../src/v4/diagnostics.py#L100-L125)：配额 2 第 40 轮在 `SOC=.75,L=100 kW` 探针上，0 kW 的可行 Q 排名是 55/61，贪婪动作为 470 kW；但该探针与轨迹中的 `SOC≈.8`、前 FC、历史负载不同，**不能用于还原当时 235 个主动 0 步的真实 Q 排序**。没有逐轮网络权重，无法离线计算准确的早期动作 TD 误差或对同一状态重排 61 个动作。

## C. 尚待验证的原因及下一步最小诊断建议

- **可确定的建模边界**：10 kW 网格加 SOC 硬上限造成 2372 个高 SOC 被迫 0 步，且当前用 `FC=0` 代表停机，随后重新启动会收取正式退化费用。这是源码语义，并非 DQN 偏好；是否允许低于 10 kW 稳定运行或“0 输出但不停机”，需设备资料，不能靠调奖励回答。
- **尚不能确认的学习原因**：主动 0 的 235 步、三条失败段末期连续 40 kW，可能涉及 Q 估计、长期风险传播、状态信息不足或训练分布。固定探针不足以给这些原因排序。若将来允许新实验，先保存合格/指定轮次网络权重及少量**实际轨迹状态**的完整掩码 Q 表，并对失败前 8/32/100 步与合法近负载动作做同状态比较；避免只提高某个惩罚系数。
- **outcome 网络的现状**：它只提供独立诊断性分类，且失败段所有动作共享结果标签；没有验证过对具体早期动作的因果归因或准确率，也未接入动作选择。不能把它已经记录失败说成经济 Q 必然知道如何避免失败。
- **不建议现在实施未经确认的持续运行门控或 n=8 正式对照**。先由设备侧确认最小稳定功率、待机、爬坡与停机定义，并用 P0 五个正式环境见证重查可行性；P2 的 n-step 方案须遵守先完成物理规则确认和验证的前置条件。

本报告没有发现可直接定位的奖励/账本实现错误。确认的主要问题是**物理网格导致的被迫停机**与**实际可行时的异常动作**需要分开处理，而 n=1 失败价值能否有效传到较早动作，现有归档还无法证明。
