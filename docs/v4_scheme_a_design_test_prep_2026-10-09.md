# V4 方案 A 工程设计与测试准备（不实施控制改动）

依据 [P0 FC 运行及可行性审计](v4_fc_runtime_feasibility_audit_2026-10-09.md)、[P1 高 SOC 与失败传播诊断](v4_high_soc_reward_failure_diagnostic_2026-10-09.md)和 [P2-A n-step 审计](v4_n_step_failure_replay_audit_2026-10-09.md)。本次仅补充合成边界测试并制定设计；未改正式控制、物理、经济账本、奖励、网络或经验采样参数，未启动训练，未读取 Test。

## 1. 已验证的前置边界

- 现行 V4 用 `previous_fc_kw>0` 表示聚合 FC 正在输出，`0 kW` **按模型约定**视为 OFF；这不是设备实测接触器状态，也没有已标定的 0 kW 带机待机状态。[正式区间模型](../src/v3/control.py#L134-L166)依据本次/上次功率收取低载、高载、变载、0→正功率启动退化；不另设人为启停罚款。SHORE_PENDING、SHORE_CHARGING 由模式机决定，DQN 停止，FC 设 0，首条岸电区间负责正→0 变载。[P0](v4_fc_runtime_feasibility_audit_2026-10-09.md)已确认第 40 轮 326 次启动中 264 次为同一 ONBOARD 段内部重启。
- P1 对 `SOC≥0.79 且 FC=0` 的 2607 步分出 **2372 步正功率网格动作不存在**及 **235 步有正功率可行却选 0**。2372 步的 10 kW 在电池功率上可行，却使下一 SOC 越过 0.8；其中 2057 步负载为 0，连续正功率余量也不足 10 kW。不能在这些步强制 FC 正出力、假定可以弃能，或把强制停机误判为 DQN 主动停机。
- P2-A 已确认 n=8 最后最多 8 个**不同起点的经济回放条目**会包含同一次失败惩罚，不能把池条目数当作真实失败数。[本次定向测试](../tests/test_v4_n_step.py)补充长度 2/7/8/9/12 的 SOC 受限失败、真实岸电边界、`failure_terminal_quota=2` 抽样及 FIFO 淘汰；该文件运行 `18 passed`。每个合成失败只在原始已执行轨迹的最后一步产生一次物理失败标签/惩罚，n=8 的终止回放条目数为 `min(8,L)`；未发现需先修复的正式 n-step 计算错误。

## 2. 两种实施层级

### 2.1 保守最小方案：沿用“0 kW = OFF”的研究模型

**规则**：先由当前模式决定是否执行 DQN。ONBOARD 中仍按[正式单步物理掩码](../src/v4/control.py#L185-L202)筛选 `0…600 kW`、电池功率和 `[0.2,0.8]` SOC。然后仅当 `previous_fc_kw>0` **且**物理掩码至少有一个正功率动作时，将 `0` 从**策略候选集合**移除；DQN 在其余合法正功率动作中选择。若物理掩码只有 `0`，必须保留 `0`，执行一次受迫停机；若物理掩码完全为空，沿用现有供电失败终止，不虚构动作。若 FC 原已 OFF（离港初始、先前受迫停机或 DQN 延迟启动），保留当前 DQN 在完整物理掩码中选择 0/正功率的权利，不强迫首次启动或受迫停机后的即时重启。

这个门控只减少“**正在正出力且可以继续正出力，却主动命令 0**”的事件。它不承诺 FC 恒定输出；正功率仍可在 10–600 kW 间变化，P1 三条失败航段末期的连续 40 kW 决策**不会被此门控直接修复**。是否提升完成率、经济成本和内部启停，要在获准正式训练后验证，不把 P0 五条可行见证误当成学习结果。

**优点**：无新增设备参数、无能量消纳假设，不碰正式 FC 四工况退化、岸电账本或奖励。门控仅依赖现有 `previous_fc_kw`、SOC、当前负载与固定物理参数。现有 [8 维 DQN 状态](../src/v4/control.py#L154-L174)已包含 `previous_fc_kw/600`，本方案不增加隐藏控制状态或网络输入维度；停机原因仅用于日志，不参与未来门控。**局限**：0 kW 的物理 OFF 仍是研究假设；受迫停机后可能继续 OFF；无法证明“稳定基础功率”，且不能消除因高 SOC/低负载造成的必然停机。改变策略可行动作集合后，旧 Q 权重不再作为正式新方案模型复用。

### 2.2 完整设备方案：显式物理 ON/OFF，依设备资料选择待机分支

先取得设备对**最小稳定正功率、0 kW 是否允许保持电堆 ON、待机氢耗及退化、启动/停机持续时间、爬坡率、最小开停机时间、实测启停定义**的证据，再决定状态图：

1. 若设备**允许 0 kW 带机**，区分 `OFF`、`ON_OUTPUT(P>0)`、`ON_IDLE(P=0)`；`ON_IDLE` 的实际氢耗/寿命损耗和转换限制必须按设备资料建模，不能设为免费。FC 启动事件只在 `OFF→ON_*` 计一次正式启停分项；`ON_OUTPUT→ON_IDLE` 不伪计停机循环，但仍按已验证模型处理变载。若现有四工况退化系数不足以描述待机，新增独立且有来源的待机量，不改写或重复已有启停分项。
2. 若设备**不允许 0 kW 带机**，则 `0 kW=OFF`，正功率须满足实测最小稳定功率及爬坡/驻留限制。高 SOC、0/低负载且没有合法正功率时仍需 OFF；若设备驻留约束又禁止该停机，则应明确报告**物理不可行**，而非假设弃能、放宽 SOC 硬约束或把不存在的功率消纳塞入电池。

完整方案的 `fc_on`、必要的驻留/启动倒计时、最近启停状态若影响下一步合法动作或成本，必须作为物理状态递推，并进入 DQN 可观测状态；不能只在环境内部记一个 DQN 看不到的锁存状态。其状态维数、网络输入和旧权重可复现边界需另立变更与从头训练，不属于本次任务。**优点**是物理语义可与真实设备一致；**代价**是依赖尚缺设备资料、状态与约束更复杂，且需重新检验全部航段可行性和经济模型。现阶段不能实施这一层。

## 3. 保守方案的状态转移与模式边界

这里“ON/OFF”均指**当前命令代理状态**，不是已测得物理接触器状态。工况仍由上层 `operating_mode` 判定，不由 DQN 选择岸电。

| 前状态 / 当前模式 | 物理掩码与策略候选 | 动作后分类；正式计费责任 |
| --- | --- | --- |
| OFF → ONBOARD 离港首步 | 有正功率时仍允许 DQN 在完整物理掩码中选择；只有 0 时选 0 | 首个正动作记“离港启动”；`0` 为未启动或延迟启动，不称“停机”。0→正启动退化仅由现有 FC 模型计一次。 |
| ON → ONBOARD 普通步 | 正功率可行时策略候选为物理正功率子集 | 只能继续正出力；现有低/高载与变载退化照常结算。可在正功率间跳变，门控本身无平滑保证。 |
| ON → ONBOARD 高 SOC / 低负载 | 物理掩码仅 `{0}` 时策略仍可选 0 | 记“受迫停机”；负载/电池/SOC 按正式模型执行。0 是真实命令，现有正→0 变载由原 FC 模型计；下一正动作的启动另在那一步计。 |
| OFF → ONBOARD 普通步 | 完整物理掩码 | 可继续 OFF，也可由 DQN 重启；日志区分“受迫停机后的启动”和“航段内延迟启动”，不引入未观测的隐含控制状态。 |
| 任意 → ONBOARD 且物理掩码为空 | 没有策略候选 | 沿用 `no_feasible_action` 失败逻辑；区分 SOC 受限与结构性超功率，不将异常伪装成失败。 |
| ONBOARD → SHORE_PENDING/SHORE_CHARGING | 不调用 DQN，不调用 ONBOARD 门控 | FC=0；若之前正出力，记“靠港停机”；正式岸电模型在首条岸电行结算变载及实际充电，不能另加一次启停费。 |
| SHORE → 再出港 | 岸电末状态 FC=0，SOC 按实际接受充电量结转 | 新 ONBOARD 段负载历史零边界重置，首步仍用实测负载；首次正出力作为新段启动。 |

一个样本若以 ONBOARD 结束且**没有实际 SHORE 行**，[modeled terminal settlement](../src/v4/control.py#L130-L151)只作等效补能账，不代表发生了靠港停机；不能凭模拟账本多记一次物理 FC 停机。`SHORE_PENDING` 同属岸电模式，即使充电请求为 0 也暂停 DQN/MPC，FC 命令按现有逻辑设 0。

### 3.1 物理掩码和策略掩码必须一致地进入 TD

未来若获准实现，不能只在 `agent.select_power(...)` 前删除 0：那会使执行策略禁止的动作仍进入 [Double DQN 下一状态 `argmax`](../src/v4/dqn.py#L23-L43)。建议保留 `feasible_fc_actions` 作为**未改变的物理硬约束**，新增一个窄函数从 `(physical_mask, previous_fc_kw)` 计算 ONBOARD **策略候选掩码**；在[执行环](../src/v4/control.py#L274-L289)用它选动作，在[transition 下一状态构造](../src/v4/control.py#L355-L372)用**同一规则**保存后继策略候选掩码供经济 Q bootstrap。失败分类仍依据原物理掩码；同时在诊断中分别记录当前物理掩码、当前候选掩码与停机原因，不能将策略排除 0 误报为物理无解。终止/岸电边界的经济 Q 后继掩码继续为空。

控制候选函数应保证“物理掩码非空 ⇒ 策略候选非空且为其子集”；在只有 0 可行时返回 `{0}`，不生成额外动作。它对未来动作的影响只取决于 `previous_fc_kw>0`，现有状态已可观测，因此不会因新增**诊断标签**破坏马尔可夫性。若未来门控改为依据“上一次停机原因”或驻留计时，则该记忆也必须进入状态。

## 4. P0 五个 Train 航段的保守门控可行性

本次仅调用正式 Train 加载器（`test_payloads_opened=0`）和正式 `replay_episode`，采用 P0 已记载的因果见证规则：每步从当前**正功率物理可行动作**中取最接近 `L+3000(0.70−SOC)` 的 10 kW 网格值，同差取较小者；再在策略入口施加“前 FC 正且正功率可行时排除 0”的拟议门控。规则只看当前实测负载、SOC 和掩码，**不是 DQN 训练，也不在在线决策中读未来负载**。

| Train 样本 | 完成 ONBOARD 步 / 段 | 最小已执行 SOC | ONBOARD 0 kW 次数 | 门控在正出力状态生效步数 |
| --- | ---: | ---: | ---: | ---: |
| `zero_boundary_015` | 337 / 1 | 0.219117 | 0 | 336 |

## 5. 后续实施顺序与正式训练前验收

1. **先定设备语义**：确认本阶段是否正式接受研究模型的 `0 kW=OFF`；若设备允许 `ON_IDLE`，先获取待机氢耗/退化与状态数据，不能将保守门控包装成真实待机控制。
2. **再实施保守策略门控**：只改第 3.2 节列出的 V4 控制/诊断与定向测试；先保证物理与策略掩码分离且后继 TD 掩码与执行策略一致。不得引入新奖励、FC 波动罚项、能量消纳或未经标定的最小功率。
3. **回归边界**：定向测试覆盖 P1 的“只有 0 可行”和“正功率可行却选 0”；测试 `SHORE_PENDING/SHORE_CHARGING`、多航段、末端模拟补能、无动作失败和普通模型异常；核对一次 0→正只收现有启动退化一次，靠港正→0 只由正式模型计对应变载。相同动作轨迹在新旧代码下的 SOC 和四项真实费用应保持一致。
4. **正式环境验收**：P0 五个 Train 可行见证仍完整执行；所有执行动作属于当前物理掩码及策略候选，完成段首尾/岸电边界正确。Test 继续封存，正式数据划分与 manifest 不变。诊断报告区分**真实失败事件数**、n-step 终止回放条目数及抽样次数。
5. **仅在前四项通过且用户另行确认后**，才可讨论新规则下的从头正式训练和 n=1/n=8 对照。不得沿用旧 checkpoint 充当新方案结果；方案 A 的可行性与经济性均需独立评估。

当前提交范围仅是 [定向测试](../tests/test_v4_n_step.py)与本文档；方案 A 的控制、经济、奖励和训练代码尚未实施。
