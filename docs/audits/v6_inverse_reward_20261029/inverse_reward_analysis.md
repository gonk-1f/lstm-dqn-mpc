# 直接倒数与终止 −1 的定义域、数值和长期行为

本报告分析用户明确指定的定义，不把它改成 tanh、1/(C+1)、偏移、clip 或其他奖励。`test_inverse_reward_analysis.py` 中的函数只是可执行数学参考，不是生产模式；真实环境/训练/Optuna 仍保持基点代码。

## 1. 正常奖励不是处处有定义

正常转移仅在 C 为有限且严格正值时定义 `r=1/C`。这是定义域，不是可以通过“遇到非正就罚 −1”修补的物理规则。

35 条 Train 的新 32 步合法前缀共 1120 步：35 个 C=0，覆盖 27 个 Train ID，**全部 done=False**；原动作 Mask 没有因费用而变动。这直接触发正式模式的停止条件。fresh 合法 idle 也给四项费用全零，不需要构造寿命已耗尽的状态。EOL 负成本边界另见预审计，其当前 Train 可达性没有被证实。

正常域内也不保证 0<r<=1。最小正费用 `6.836828188453796e-7 CNY` 对应 `1462666.5647219638`，不是归一化奖励。JSON 的逆值缺失计数 35 不是给零奖励；其 mean/分位数只描述有效正成本子集。

生产如果未来获授权实施，需在费用/奖励边界立即检查：非正 C、非有限 C、倒数 overflow，以及写入 float32 Replay 后是否仍有限；不能静默过滤坏样本。测试给出有限正 double `1e-320` 的倒数可溢出，`1e-40` 的 double 倒数虽有限却超过 float32。它们是数学数值反例，不是宣称当前数据出现这些极端值。

## 2. 金额、等效价值与 reward 单位

C 的数值合同是 CNY，倒数有 CNY^-1 量纲；终止 −1 是强化学习分数，不是负一元物理费用。若把标量 reward 解释为无量纲数，必须明确它取“以 CNY 数值表示的费用的倒数”，冻结单位约定；不能声称它是原经济账本金额。

因为 −1 固定，若把费用单位改成分而不调整其他定义，正常奖励缩小 100 倍，失败信号的相对强度就改变，甚至改变完成/失败的排序。报告此点不等于引入用户禁止的 C0 或实施缩放。

## 3. 累计倒数不等于最小化累计经济成本

对正 C，单步变换严格单调，所以**在同一状态仅比较即时成本**时，成本越低倒数越高。但累计和、随机期望及 Q 值不是把旧累计成本简单取倒数。

相同步数反例：A=[1,1]，总成本 2、倒数和 2；B=[.1,10]，总成本 10.1、倒数和 10.1。B 更昂贵但更受新目标偏好。即使总成本相等，A=[1,1] 与 B=[.1,1.9]，后一条的累计倒数也更高；凸性使低费用/不均匀分布得到更大权重。风险动作在相同期望成本下也可能有更高期望倒数，不能称天然风险规避。

### 真实 Train 同航段对照

同一最短 `parent_046_seg02`，初始任务合同相同、13 个原合法动作、3272 步均正常完成，每步成本都正：

| 本次固定合法策略 | 当前完整经济成本/CNY | 累计直接倒数 | 末 SOC |
| --- | ---: | ---: | ---: |
| hold_300 | 798.4205950173333 | 29280.01353306763 | .6885063409367764 |
| load_follow | 1074.6392001551526 | 145747.46016531377 | .60005092012941 |

累计倒数更偏好费用高约 276.22 元的后者，倒数回报约为前者 4.98 倍。两者末 SOC 不同，但当前经济合同已经包含 signed SOC 修正，故这是当前完整任务经济指标下有效的反例；不能改称相同末 SOC 试验。数据在 [train_full_steps.csv](train_full_steps.csv)，由实际冻结物理执行，无网络学习。它不代表新实时估值方案，因为后者尚未选定；也不证明两条固定策略中的任何一条最优。

即使以后库存/势函数使某两条费用总和保持不变，逐步费用确认时点变动仍可改变倒数和。例如 [1,1] 与 [1.5,.5] 都合计 2，倒数和却为 2 与 8/3。因此不能用费用端点恒等来证明倒数控制目标等价。

## 4. 终止 −1 的准确语义及局限

若真实执行一步后，下一决策的物理或增量可行集为空，用户的定义可采用：**替换最后一条真实 transition 的训练奖励为 −1，done=True、后继 Mask 为空**。不再加旧 10132.66，也不另加虚构失败动作，不先算尾步倒数再额外扣 −1。物理费用账本仍保存该实际步的费用，不能把 −1 元写进 ledger。

正常完成保留最后一步正倒数，不额外给 −1。合法的零/负经济费用不是物理不可行，不可套失败标签。数据错误、文件故障、NaN、Inf 或程序异常仍必须报错；真实 failure 标签也不能用来隐藏损坏的非有限账本。

替换为 −1 时，最后一步原本的倒数无需计算；有限零/负费用与数学 overflow 尾值本身不改变已由物理过程确定的 terminal reward。**这不放宽正常转移域检查**：本次实际观测的 35 个零成本全部非终止，依然阻断。

如果首决策已经无动作，旧环境产生 event-only `InfeasibleReset`，没有最后真实 transition 可以替换。不能为了实现 −1 捏造 TD 样本；若未来需要单列 episode 失败分数，必须和训练经验/TD 目标区别说明。这一边界没有在本分支悄悄重定义。

已有 `masked_td_targets` 用终止 done 清除 bootstrap，参考测试以 reward=−1、空 Mask、巨大 next-Q 验证 terminal target 仍为 −1。它只证明已有算子的能力，不表示新 reward 已接入。

### 正奖励加负终止不保证所有策略中完成优先

相同已奖励前缀后，延长正奖励并完成确实优于把尾步替成 −1。但不同动作可以进入不同费用路径。数学反例：完成路径成本 [1,1,1]，回报 3；失败路径实际成本 [.01,10]，尾步替换后回报 100−1=99。正常奖励正、失败奖励负仍未保证整体排序。

固定 −1 相对某尾步的下降量是 `1/C_last+1`，不是固定一单位的附加惩罚。C=.01 时下降 101，C=1000 时仅下降 1.001；费用确认和低费用前缀会影响它的有效信号。这里不通过额外惩罚修正用户定义。

## 5. gamma=1、长度、1 秒尺度及 13 动作 Q

恒定每步费用 .07 时，1000 步回报约 14285.7，10000 步是其十倍。原 35 航段长度不同，因此混合逐 episode Return 波动不能直接当作策略收敛或费用改善；选模仍应只看独立 Validation 的既定层级。

固定物理费用率 k、总时长 T、间隔 dt 时，`sum 1/C_t = T/(k*dt^2)`。同样 30 秒和总费用，以 1 秒逐步计算的回报是一次 30 秒计算的 900 倍。本次保持 1 秒不变，但这解释为何小额单步费用会放大数值，不能从旧低频实验套用 Q 尺度。

13 动作 Mask 不应改变。即时正成本排序仍单调；长期 Q 的排序却可能受将来的低费用片段、终止路径、长度及估值状态影响，不能对旧 Q 逐元素取倒数得到新 Q。当前没有训练新模式，因此没有冒充实测的 13 动作 Q 排名。

Huber beta=1 限制大残差对残差本身的导数，梯度裁剪限制参数梯度，但都不限定 Q 或 TD target 的幅值。正费用的百万级倒数经 gamma=1 累积会改变 TD 目标量级；float32 在大 Q 处可能丢掉小动作差异。测试展示 `1e8` 附近 +1 无法区分，属于精度风险示例，不是当前网络已经不稳定的证据。源码非有限值检查、实际 minibatch Loss/TDMAE 和性能仍应在获准新设计后再验证。

## 6. 后续接口工作是条件性的

未来只有在定义域和实时估值设计获得明确解决后，才可同时适配 Direct 环境、episode runner、Validation、Optuna、统计、snapshot 和 identity；不能只把字符串加进 parser。尤其旧 step-tuning 的 executor 非历史分支会走 Zhou，而新 episode-tuning 当前固定 Zhou，直接添 choice 可能错误回退。

届时 metadata 必须绑定 reward 定义、成本单位、新经济版本、初始价值/状态约定及 terminal 语义，并拒绝跨 reward 的目录/study/checkpoint；生产批量、32:1、Target 时钟和 gamma 不应改变。金额 EconomicCost 与 inverse Return 必须分开。当前分支没有进行这些生产改动或宣称这些新模式测试已经通过。
