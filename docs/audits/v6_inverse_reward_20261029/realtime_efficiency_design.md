# 实时 FC 效率下的储能价值：方案比较

本文件为推导和审计候选，**不是已接入生产的经济模型**。数值由 [test_realtime_value_design.py](../../../tests/test_realtime_value_design.py) 的独立数学案例复现，使用原 FC 曲线与 .95/.95 电池效率，不改物理参数、控制状态或训练机制。

## 1. 已知量与不能推断的量

本航段为无岸电 ONBOARD，当前充电母线功率为 `P_charge=P_fc-P_load>0`，来自当前 FC。**初始 SOC=.6 的储能来源及历史成本没有随 episode 数据提供**，不能由“本航段无岸电”推断初始能量也由本步 FC 生成。

当前 FC 真实耗氢是 `m=P_fc*dt_h/(eta(P_fc)*LHV)`，FC=0 直接为零；SOC 积分已经把充电输入乘 .95、放电输出除 .95。因此直接把原 SOC 公式的固定 eta 改成 eta(P_fc)，会在 FC 关闭的正常放电处除以零。用任意 eta 常数填补不是实时模型依据。

## 2. 充电有两种不同的价值语义

设储存的电芯能量 `dE_plus=eta_chg*P_charge*dt_h`：

| 语义 | 氢等效量 | 含义 |
| --- | --- | --- |
| 当前生成效率下的留存电能价值 | `dE_plus/(eta_fc*LHV)` | 仅按留存电能计价，充电损耗在当前费用中保留 |
| 充电份额的全部实际发电成本入库 | `a=dE_plus/(eta_chg*eta_fc*LHV)` | 将供充电的实际氢耗资本化，含充电损耗导致的单位储能成本 |

第二种严格等于 `m_actual*P_charge/P_fc`，在该域 `P_fc>0` 且 `0<=P_charge<=P_fc`，所以 `0<=a<=m_actual`，不会无依据抵扣更多本步真实氢气。第一种为第二种的 .95 倍，也不超出实际量。两者费用确认时点不同，不能把第一种说成已分配全部历史发电成本，也不能把第二种的 eta_chg 当作对 SOC 的重复物理积分。

可复核例：FC=60 kW、load=20 kW、1 秒，eta=.624984128656：

```text
实际氢气 m_actual = .000800020316 kg
储能 dE_plus       = .010555555556 kWh
充电分配氢气 a    = .000533346877 kg = .011680296611 CNY
直接负载分配       = m_actual-a
留存价值           = .95*a
```

FC 关闭后以 36.1 kW 放电一秒，电芯取能为相同 .010555555556 kWh，母线交付能量为原充电母线能量的 .9025。这个能量环不需要 eta(0)，也不能忽略放电损耗。

## 3. 候选 A：加权历史氢成本库存

以 `E_t` 表示选定能量池内的 kWh，`H_t` 表示其氢成本基准（kg 或明确约定的成本等价 kg）。充电按上节全发电成本入库；放电从同一池按加权成本出库：

```text
w_t = 本步取出的电芯能量（已含 eta_dis）
d_t = (H_t/E_t)*w_t              放电且 E_t>0
E_after = E_t + dE_plus - w_t
H_after = H_t + a_t - d_t
m_SOCeq,t = d_t-a_t = H_t-H_after
```

物理禁止从空的可用池继续放电；无能量流时不必做 `0/0`。FC 关闭放电用既有池的价值，不引用 eta(0)。本推导只资本化氢气，不把 FC 或电池退化加入 H，后者仍在原实际 ledger 中记一次。

因此整段具有严格端点恒等：`sum m_SOCeq=H_initial-H_terminal`，完整等效费用是 `hydrogen_price*(sum m_actual+H_initial-H_terminal)+原退化费用`。完整回到同一 **E 和 H** 时，修正抵消，实际耗氢只计一次。只回到相同 SOC/E 不够，因为加权成本基准可能改变；这是库存费用确认逻辑，不能冒充旧“仅首末 SOC”口径。

例：E=1、H=.06，充入 1 kWh、其氢基准 .05 后，池为 E=2/H=.11；再取出 1 kWh，出库 .055，最终 E=1/H=.055。修正和为 .005 kg，实际新耗氢 .05 加修正为 .055 kg。它确认了从混合池消耗的成本，同时留下较低的新成本基准，没有物理创造氢气。原固定系数的等 SOC 修正则为零；两者经济口径不同。

### 初始基准与状态是待决设计

案例把可用池定义为 `(SOC-.2)*624`，初始为 249.6 kWh；全电芯储能则是 .6*624=374.4 kWh。是否排除硬下限储备、储备如何参与成本混合、H0 从实测上游成本还是明确的替代成本假设初始化，都不是原源码已经决定的事实。把 H0=0 当“免费初始能量”是另一种任务定义，不是除零修复。

H 会影响下一步费用。相同 SOC、当前 FC 和三个因果负载特征可以对应不同 H，下一次放电费用不同；本项目 history5 是五个特征，并不是完整功率历史。案例还给出同样零负载、合法增量前序 `40,40,40,0` 与 `60,60,0,0`，输入/终态能量相同但生成效率不同，库存基准不同。只在 checkpoint 存 H 能恢复会计状态，**不能让 policy 观察不到的 H 自动变得可辨识**。

若要求模型对该新增价值状态有充分观测，需决定是否把成本基准/单位能量价值加入输入；当前任务禁止自行改网络结构，不能默默做这个变更。也不能把这个结论夸大成任何部分可观测控制都无法工作：它说明必须明确接受额外隐藏状态或授权改变表达，不能宣称 history5 已完整表示新价值。

## 4. 候选 B：动态边际补能价值或完整势函数

可以定义有经济依据的反事实补能功率/机会或未来成本影子价格，但当前 eta(P_fc) 本身不唯一决定放电的替代机会。容量、增量约束、FC 当前是否关闭、何时补能、初始储备价值都影响该选择。即便在正功率，氢函数 `g(P)=P/(eta(P)*LHV)` 的边际导数也不是简单的 `1/(eta(P)*LHV)`；零点和启动有离散性，不能凭一个任意正功率参考就称已证明最优边际值。

若选择随可见状态变化的价值 `Phi_t=k_t*E_t`，完整差分为：

```text
Phi_t-Phi_after
 = k_t*(E_t-E_after) + E_after*(k_t-k_after)
```

仅使用第一项会遗漏重估。E=[1,1.1,1]、k=[.06,.05,.06] 时，能量项合计 −.001 kg，重估项 +.001，完整势差为零。不能把漏项造成的循环抵扣称为守恒。独立价格重估即使没有能量流也可改变账面价值，但必须解释价格过程、状态可观测性及确认规则；本项目没有授权凭空引入一个使 idle 费用永远为正的估值过程。

完全由可见状态决定的势函数原则上可保持该部分价值状态的可计算性，因此**不是所有动态方案都数学不可能**。但 SOC-only 的单一势函数不可能同时匹配不同 eta 下相同 dE 的实际充电分配：例如 FC60/load50 与 FC100/load90 有相同充电剩余功率而生成效率不同。若扩大势函数自变量，必须包含相应的重估语义，而不是只换分母。

## 5. 当前不能宣称已实现的内容

库存方案有自洽代数，但 H0、池定义、可观察性和最终经济目标尚未选定；边际方案也缺少明确的补能机会/价值函数。不能输出一个假装已经验证的完整实时 Train 成本。预审计只给“单独改充电分支”的条件差值，完整实时费用保持 null。

此外，即使总费用在端点保持相同，非线性倒数也不保持回报：费用 [1,1] 与 [1.5,.5] 都合计 2，但倒数和为 2 与 8/3。因而选择储能费用确认时点还会改变倒数训练目标，不能以“总经济恒等”代替策略目标不变的证明。

在现有无流且估值状态不变的 idle 处，库存/固定势值都给零修正。真实 Train 已观测到该点；实时效率并不会自动修复严格倒数的零域。故本分支保留方案比较与数学测试，不启用生产实时模型或奖励。
