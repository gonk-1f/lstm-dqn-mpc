# SimulationCode TD3 对照实验

模型以压缩包内 `SimulationCode/train_td3_ship.py` 的 `ShipPowerEnv` 为主，并核对 `SimulationCode/shipenv.py`。训练沿用原生 SB3 2.2.1 和原有 TD3 配置，负载仍用项目 1 s 数据。每轮从 `parent_005_seg01` 取连续 5,001 个采样点，执行 5,000 步。完整航段诊断使用同一环境和归一化尺度。

| 模块 | 实现与源代码核对 |
| --- | --- |
| FC 功率 | 这是单一 600 kW 输出模型。命令范围是 0–600 kW，滤波后实际输出限在 1–600 kW。参考脚本以 **kW/s** 定义 20 的指令爬坡上限，保持绝对值。10 s 滤波权重为 `exp(-1/10)`，实际输出每秒最大变化约 1.9033 kW。初值为 `clip(0.5 × 初始负载, 10, 600)`，与滤波初值一致。 |
| 氢耗 | 将原 80 kW 标定点映射到 600 kW 的相同负载率。最高标定点对应约 598.30 kW，之后沿用插值端点 44.5552%。低热值为 120,000 kJ/kg，`P/(η × LHV)` 得 kg/s，乘 3,600 得 kg/h。电池用同一瞬时效率和带符号功率。源 `_calc_h2()` 标为 kg/h 的数值实际为 g/s，换算后保留源单步成本的数值。 |
| FC 退化 | 保持源额定归一化坐标 0.3125，因此分母由 2,560 改为 1,920 kW。高负载 ≥480 kW，低负载 ≤120 kW，分别使用 10.00、8.66 μV/h。原训练脚本对归一化功率使用 `>0.1`，使低负载退化无法触发。这里采用 `shipenv.py` 的物理阈值 0.1 kW，并保留训练脚本的 13.79 μV 上升沿计数。原 `shipenv.py` 会将 `N_cycle` 强制置零。本环境正常运行的 FC 初值和最小实际输出均高于阈值，因此常规航段没有启动事件。 |
| FC 瞬态及寿命 | `0.0441 × abs(ΔP)/1920`，沿用源脚本使用的归一化功率差。原注释把系数写作 μV/kW，与代码中乘归一化差值的做法矛盾。EOL 为 60,000 μV。原始 FC 成本为 `(7500/7) × 600 × 四项电压损失 / 60000`，奖励取 `min(原始值, 0.05)`，轨迹保留两者。 |
| LB 退化 | 电池能量为 624 kWh，电压 432 V，独立读取充电与放电限值，当前均为 624 kW。令 `c=abs(P_bat)/624`。Qloss 的三项为 `(abs(P_bat)/3600)^0.55`、`32350 exp(-0.3375c) + 4041 exp(0.1271c)`、`exp(-(63400-(c+1)370.3)/(8.31×350))`。相乘后按源式乘步长 1 s，成本系数为 `350×624/20/100`。 |
| SOC | 每轮均匀抽取 0.40–0.70。源恒压式化简为 `SOC_next = SOC - P_bat/(624×3600)`，正功率为放电。432 V 用于电流计算。该对照沿用源模型的 SOC 式，充放电效率按 1 处理。源 0.30–0.80 边界基于步前 SOC 禁止继续越界方向的动作，允许前一步越界过渡，并在可执行的边界外步骤收取 0.1。 |

观测为 SOC、当前负载、下一秒负载减当前负载、上一时刻实际 FC 功率。负载尺度使用 Train35 最大负载，变化量尺度使用 Train35 的最大相邻 1 s 差值。四维输入均限制在 `[-1, 1]`。差分读取同一窗口内的相邻采样点，最后一个观测的差分为零。SOC 抽样使用单独派生的随机数流，保持种子 42 对应的窗口起点序列。

正常奖励为 `-(实际氢耗成本 + 有符号等效氢耗成本 + LB退化成本 + 截断后FC退化成本 + 10(SOC_next−0.5)^2 + SOC边界惩罚)`。氢价系数沿用源代码的 4，压缩包未标注货币。因为实际与等效氢耗使用同一效率，且物理执行时功率平衡，两项之和等于负载功率除以当步效率与低热值后计价。完整经济合计保留截断前 FC 成本。

当滤波后的 FC 与受限电池无法满足负载时，该步不执行物理供能，`terminated=True`，`truncated=False`。奖励为 `-2 × 剩余步数`，包含当前未执行步。构造环境时核对这个系数大于单步正常成本上界。原训练回调会在首个未完成窗口停止试验，写入失败记录。正常窗口结束仅记录 `training_window_end`。

使用基线的 SB3 2.2.1 解释器，从当前工作树运行 `src/scripts/train_td3_reference_model.py`。输出写入 `outputs/td3_reference_model/`，每 20 轮记录完整 Train 航段及检查点，第 100 轮运行 Validation8。
