# SimulationCode TD3 可行区间动作与四项成本实验

模型以压缩包内 `SimulationCode/train_td3_ship.py` 的 `ShipPowerEnv` 为主，并核对 `SimulationCode/shipenv.py`。训练沿用原生 SB3 2.2.1 和原有 TD3 配置，负载仍用项目 1 s 数据。每轮从 `parent_005_seg01` 取连续 5,001 个采样点，执行 5,000 步。完整航段诊断使用同一环境和归一化尺度。

| 模块 | 实现与源代码核对 |
| --- | --- |
| FC 功率 | 初值仍为 `clip(0.5 × 初始负载, 10, 600)`。相对动作 `a ∈ [0,1]` 映射为 `P_fc = fc_min + a × (fc_max − fc_min)` 后直接执行。状态和瞬态退化使用实际执行功率。 |
| 氢耗 | 将原 80 kW 标定点映射到 600 kW 的相同负载率。最高标定点对应约 598.30 kW，之后沿用插值端点 44.5552%。低热值为 120,000 kJ/kg，`P/(η × LHV)` 得 kg/s，乘 3,600 得 kg/h。电池用同一瞬时效率和带符号功率。源 `_calc_h2()` 标为 kg/h 的数值实际为 g/s，换算后保留源单步成本的数值。 |
| FC 退化 | 保持源额定归一化坐标 0.3125，因此分母由 2,560 改为 1,920 kW。高负载 ≥480 kW，低负载 ≤120 kW，分别使用 10.00、8.66 μV/h。原训练脚本对归一化功率使用 `>0.1`，使低负载退化无法触发。这里采用 `shipenv.py` 的物理阈值 0.1 kW，并保留训练脚本的 13.79 μV 上升沿计数。实际输出由 ≤0.1 kW 转为 >0.1 kW 时记录启动退化。 |
| FC 瞬态及寿命 | `0.0441 × abs(ΔP)/1920`，沿用源脚本使用的归一化功率差。原注释把系数写作 μV/kW，与代码中乘归一化差值的做法矛盾。EOL 为 60,000 μV。FC 成本为 `(7500/7) × 600 × 四项电压损失 / 60000`，直接进入奖励。 |
| LB 退化 | 电池能量为 624 kWh，电压 432 V，独立读取充电与放电限值，当前均为 624 kW。令 `c=abs(P_bat)/624`。Qloss 的三项为 `(abs(P_bat)/3600)^0.55`、`32350 exp(-0.3375c) + 4041 exp(0.1271c)`、`exp(-(63400-(c+1)370.3)/(8.31×350))`。相乘后按源式乘步长 1 s，成本系数为 `350×624/20/100`。 |
| SOC | 每轮固定从 0.65 开始。源恒压式化简为 `SOC_next = SOC - P_bat/(624×3600)`，正功率为放电。432 V 用于电流计算，充放电效率按 1 处理。电池可行功率为 `[max(-624, (SOC−0.80)×624×3600), min(624, (SOC−0.30)×624×3600)]`。据此取 FC 可行区间 `[max(0, P_load−P_bat,max), min(600, P_load−P_bat,min)]`。 |

观测为 SOC、当前负载、下一秒负载减当前负载、上一时刻实际 FC 功率。负载尺度使用 Train35 最大负载，变化量尺度使用 Train35 的最大相邻 1 s 差值。四维输入均限制在 `[-1, 1]`。差分读取同一窗口内的相邻采样点，最后一个观测的差分为零。随机窗口起点继续由种子 42 生成。

正常奖励为 `-(FC实际氢耗成本 + FC退化成本 + LB退化成本 + 10(SOC_next−0.5)^2)`。氢价系数沿用源代码的 4，压缩包未标注货币。有符号等效氢耗只保留在经济账本和逐步审计中。

FC 可行区间为空时，该步不执行物理供能，`terminated=True`，`truncated=False`。奖励为 `-2 × 剩余步数`，包含当前未执行步。原训练回调会在首个未完成窗口停止试验，写入失败记录。正常窗口结束记录 `training_window_end`。

FC 输出 0 kW 时，等效氢耗审计沿用效率下限 `1e-6`。电池独供 624 kW 的审计成本为 20,800，FC 实际氢耗成本为零。取消原退化成本截断后，按现有系数计算，单次启动的退化成本为 147.75。预热将正常步成本大于每剩余步失败惩罚 2 作为量级异常，保存有效步并停止采集。该诊断门槛独立于环境奖励和物理失败标志。

使用基线的 SB3 2.2.1 解释器，从当前工作树运行 `src/scripts/diagnose_td3_no_fc_warmup.py` 采集原生预热 rollout。诊断最多执行 25,000 步，首次物理失败或奖励异常时写出轨迹并退出。结果写入 `outputs/td3_feasible_action/warmup_*/`。

种子 42 的实际诊断在首个窗口 [380, 5380) 执行 53 步。第 52 步 FC 输出为零，等效氢耗审计成本 3,045.55，奖励为 −0.2724。第 53 步 FC 升至 462.00 kW，FC 退化成本为 147.86，奖励为 −148.13。逐步功率平衡误差不超过 3.6×10⁻¹⁴ kW。诊断因正常成本超出失败代价尺度停止，物理失败和梯度更新均为零，20 轮试验未启动。

通过预热诊断后，将汇总路径传给 `src/scripts/train_td3_reference_model.py --warmup-summary <路径>`。20 轮试验从新模型开始，每 5 轮记录完整 Train 航段的确定性诊断、两种功率分布、Loss、Q 值及检查点。
