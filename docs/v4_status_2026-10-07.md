# v4 直接功率 Double-DQN：进度、参数与未解决问题（2026-10-07）

本文记录 `feat/direct-power-mlp-ddqn` 分支的**实际代码和单种子实验状态**。v2 的 DQN 调 MPC 权重、v3 的持续预测/LPF、LSTM 和 KAN 均不在当前 v4 控制链中。旧版本文档中的 `N=5`、`M=5`、36 动作和 MPC 权重不是本版本的训练参数。详细实现见 [v4 方法说明](v4_direct_power.md) 和 [失败审核](v4_training_failure_audit_2026-10-06.md)。

## 当前控制链与数据

每个 30 s `ONBOARD` 区间先读取**当前**实测负载，再由 MLP Double-DQN 选 FC 功率 `0, 10, ..., 600 kW`（61 个离散动作），电池母线功率为 `P_bat=P_load-P_FC`。一阶段动作掩码排除超出电池功率或 SOC 界限的选择；它不保证以后几步仍有可行供电动作。v4 不预测未来负载，不求解 MPC，也不用 LPF；`EconomicMPC` 类只提供已存在的单步物理/经济核算。无动作后的功率不被裁剪或虚构。

控制状态的 8 个标量依次为：SOC；当前负载/600；当前与上一负载差/600；上一与再上一负载差/600；上一 FC 功率/600；FC 累计经济寿命消耗比例；电池累计经济寿命消耗比例；出港标记。出港时负载历史和上一 FC 命令以 0 为控制边界，首步执行的仍是实测负载。样本默认初始 SOC 为 0.6。样本内部经过岸电后，下一次出港继承实际充到的 SOC。

工况由数据中的 `operating_mode` 给定。`SHORE_PENDING/SHORE_CHARGING` 无 DQN 动作、FC 为 0；负的电池母线功率是充电请求，接受量受电池充电功率与 SOC 0.6 上限约束。实际接受量更新 SOC、电池退化和购电费用。岸电紧随航段时，该岸电块成本计入前一 ONBOARD 终止 transition 一次；下一出港开始新的决策序列。FC 停机变载与下次启动均通过原 FC 退化模型核算，无独立停机收费项。

正式数据 manifest 为 Train/Validation/Test = **30/8/5** 个样本，Train 有 **23,590** 个 30 s 物理区间。训练入口只加载 Train、Validation；已核实的训练报告中 `test_payloads_opened=0`。最终 Test 读取时要求原始负载序列首尾为 0 kW；原始末尾 0 kW 是**不执行的边界行**。Train/Validation 最后一个可执行行均为 ONBOARD，不能由这个边界行推定已发生岸电补能。

## 当前 DQN 训练配置

| 参数 | 当前值或语义 |
| --- | --- |
| 网络 | 8 输入 → ReLU 128 → ReLU 64 → 61 个 Q 值；在线/目标网络 |
| 算法 | 可行动作掩码 Double-DQN；Smooth L1 TD loss；Adam |
| 折扣、学习率 | `gamma=1.0`；`1e-4` |
| 回放、批量 | FIFO 容量 100,000 条；batch 64；均匀随机采样 |
| 梯度 | 范数裁剪 10；每**完成**一个训练样本更新 16 次；每轮同步目标网络 |
| 预填充 | 用当前负载跟随策略生成可完成轨迹，随后每完成样本再进行 16 次预训练更新 |
| 探索 | 每轮固定 ε，跨 40 轮线性下降；原默认 `0.15→0.02`，对照 `1.0→0.05`；验证 ε=0 |
| 随机种子 | 对照实验均为 42；没有多种子稳定性结论 |
| 输出 | 每 50 个已选择 ONBOARD 动作打印一次；这一计数不是梯度更新数 |

训练失败时记录航段和行号，继续下一个样本；**失败前整段动作与成本尚未进入经验回放**。目前也没有将失败编码为学习目标或 CNY 罚款。选择模型的门槛是 Validation 8/8 完成；未达到时无正式 `selected_agent.pt`。`outputs/v4_direct_power*/` 是本地忽略目录，以下数字保存在此文档以便远端阅读，原始日志不随 Git 推送。

## 当前物理与经济参数

这些是代码采用的**研究仿真方案**，不是实船测量参数；旧文档中的真实船舶规格也不是当前 `PlantConfig.research_simulation()` 的输入。

| 模型 | 生效参数与算法 |
| --- | --- |
| 功率与能量 | FC 额定 600 kW；电池额定 624 kWh；电池母线充电下限 -624 kW、放电上限 1,248 kW；`P_bat>0` 为放电 |
| SOC | 航行硬界限 0.2–0.8；默认起点 0.6；岸电接受目标最多 0.6 |
| 电池效率 | 充电 0.95，放电 0.95；航行 SOC 按母线功率与效率更新；岸电记录视作电池侧充电请求，购电量由接受的电池侧能量除以 0.95 |
| FC 氢耗 | FC 效率用 `FC_Data.xlsx` 中 100 kW 参考曲线按相同负载率映射至 600 kW，经 PCHIP 插值；氢低位热值 120 MJ/kg（33.333… kWh/kg） |
| FC 退化 | 100 kW 参考单位的低/高负载运行损失 10.17/11.74 µV/h，高负载界线 0.8；变载 0.0441 µV/参考单位 ΔkW；启动周期 23.91 µV/次；600 kW 聚合功率映射比例 1/6；寿命终点 70,000 µV。停机变载由 `abs(ΔP)` 项记录，周期项在 0→正功率时计一次 |
| 电池退化 | 额定电压 432 V，额定电量 624 kWh；电流 `I=P_bat×1000/432`；每步以 `|I|Δt/3600` Ah 乘 SOC 应力 `1+3.25(1-SOC)^2` 和电流应力（放电 `1+0.45 I/I_1C`，充电 `1+0.55 |I|/I_1C`）；寿命归一化为 15,000 倍额定 Ah。该寿命因子属文献/项目假设 |

实际一步经济账本和训练奖励为

```text
C = C_H2 + C_FC_deg + C_Bat_deg + C_shore_electricity
r = -C                         # 原始人民币；不除 Cscale
C_H2 = m_H2 * 21.9 CNY/kg
C_FC_deg = Δmin(D_FC, 1) * (600 kW * 3500 CNY/kW * 0.5)
C_Bat_deg = Δmin(D_Bat, 1) * (624 kWh * 2000 CNY/kWh)
C_shore_electricity = E_grid * 1.10 CNY/kWh
```

其中 `D_FC=累计单电池电压损失/70,000 µV`，`D_Bat=累计加权 Ah/(15,000×624,000/432 Ah)`。氢价 21.9 元/kg，设备价 FC 3500 元/kW、电池 2000 元/kWh，岸电电价 1.10 元/kWh；岸电价是情景值，非码头实测电价。岸充电池退化留在 `C_Bat_deg`，不再放进购电费用重复计数。FC 给电池充电造成的额外氢耗、FC 退化和电池充电退化已随物理功率结算。**当前没有**额外 SOC 偏离项、FC 跟踪/波动项、MPC 目标、失败 CNY 罚款或未观测到的末端岸充费用。

具体价格出处与证据等级见 [v2 经济参数](v2_economic_parameters.md)；本版本实际调用的常量在 `src/v2/economics.py`、`src/v2/models/` 和 `src/v3/control.py`。`EconomicMPC(nominal_cost_cny=1.0)` 只复用 `interval`/`shore_interval`，这个 `1.0` **不是** v4 奖励或成本的归一化尺度。

## 实验进度与未解决问题

两组对照都用了 40 轮、全部 30 个 Train 和 8 个 Validation、seed 42、batch 64、每完成样本 16 次更新；其余代码与原始经济奖励相同。

| ε 日程 | 第一轮 Train | 40 轮累计完成/1,200 次尝试 | 最后一轮 Train | 贪婪 Validation | 总梯度更新（含预填充） |
| --- | ---: | ---: | ---: | ---: | ---: |
| 0.15→0.02 | 13/30 | 438 | 10/30 | 4/8 | 7,472 |
| 1.0→0.05 | 20/30 | 584 | 10/30 | 4/8 | 9,808 |

高 ε 增加了完整轨迹和训练更新，但**没有改善最终贪婪验证的完成率**。两次运行均无可选正式模型，Test 未打开。它们是一个种子的诊断结果，不支持“训练已收敛”或“哪一种 ε 普遍更优”。当前负载跟随基线为 Train 29/30、Validation 7/8；每步选当前可行最高 FC 功率的物理完成率为 30/30、8/8，它只是可行性诊断，不能据此宣布经济最优。

主要问题按证据区分：

1. **未来供电可行性**：掩码只检查当前一步。某些高负载航段在电池 SOC 被提前放到 0.2 附近后，即使 FC 输出 600 kW 也不能同时满足当前负载和 SOC 下限。它不是 600 kW 额定上限的实现错误。
2. **失败数据未学习**：当前失败样本前缀被丢弃，负经济成本的 Q 目标没有看到导致后续供电失败的选择。直接把失败标记为终止、却不定义失败结果，会让少付未来成本的失败轨迹看似有利；需要先明确约束/学习语义。
3. **末端能量口径**：Train/Validation 的最后执行区间仍是 ONBOARD，随后没有实测岸电区间。原始负载曲线的末端 0 kW 边界不等于充电，因此部分末端电池欠账没有计价。正式比较全航段经济性前，需要预先确定相同末端 SOC 条件或有依据的补能账本；不能凭空生成“实际岸电费”。
4. **控制目标与可观测信息**：当前纯经济奖励不会数学上保证“FC 平稳供基荷、电池削峰填谷”。FC 退化已经计入变载，若日后另加控制项，应明确其独立指标与成本代价，避免重复计罚。状态没有未来负载或航程信息；相同历史而未来高负载长度不同的航段，当前策略无法据此区分。

下一阶段应先固定供电失败的训练反馈与末端能量评价口径，再按**完成率、全航段四项费用、终端 SOC、FC 波动、电池峰值功率**评估；随后才有证据判断是否需要额外控制项或 KAN 网络。上述改动尚未实现，当前分支仅是可复现的 MLP Double-DQN 研究阶段。

## 复现命令

在此工作树的 PowerShell 终端运行（输出写入本地忽略目录）：

```powershell
$env:PYTHONPATH=(Resolve-Path .\src).Path
python -u -m v4.train --rounds 40 --updates-per-episode 16 --batch-size 64 --seed 42 --epsilon-start 0.15 --epsilon-end 0.02 --progress-every-steps 50 --output-dir .\outputs\v4_direct_power_40r_u16_seed42
python -u -m v4.train --rounds 40 --updates-per-episode 16 --batch-size 64 --seed 42 --epsilon-start 1.0 --epsilon-end 0.05 --progress-every-steps 50 --output-dir .\outputs\v4_direct_power_40r_u16_eps1_to_005_seed42
```

若 Validation 未全完成，入口仍写 `report.json`，但返回非零状态且不保留 `selected_agent.pt`；这表示**不满足选模门槛**，并非脚本在第 40 轮前异常终止。
