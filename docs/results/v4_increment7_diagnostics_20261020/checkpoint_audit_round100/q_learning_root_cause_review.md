## 1. 结论与前次报告勘误

1. **015、044均有可复现的完整合法增量动作见证。** 本轮仅定向重建这两条旧见证，动作序列SHA与旧CSV一致，并以当前正式 `increment7 / zhou_joint` 环境完整执行。前次报告所说“本次未证明015全航段可行”，是遗漏既有证据；不能继续将其列为项目尚未证明的事项。局部最大SOC干预失败只说明该干预进入死端。
2. **保持动作并非全局缺少经验。** 30万条Replay中保持动作88,994条，占29.6647%。020附近的保持经验较部分变载经验更稀疏、预计抽样更少，但不是没有经验，也不能仅凭近邻数宣布覆盖充分。
3. **Q与当前冻结目标确有动作差异拟合偏差。** 020有40/64组、015有84/154组可比actual/hold动作对的DeltaQ、DeltaY异号。020两个动作的残差均偏负，实际变载动作更明显，支持“变载Q相对当前参考目标偏高”，不能直接改写为“保持的最优长期Q被低估”。
4. **没有发现Target漏更新或重复硬同步。** 初始完整复制1次，34,807次经济更新对应34,807次软更新。EMA存在滞后，但去除共同偏移后动作优势仍有差异，且现有快照不能证明Target滞后是主要原因。
5. **存在各类经验拟合表现分化，尚无直接参数梯度干扰证明。** 正常终止MAE在R62至R100改善，其余三类恶化；这些来自不同采样分布和不断变化的模型，不能当成受控共同拟合实验。
6. **当前最值得优先验证的一项改动：经济Q更新密度 `replay32 → replay16`。** 这是待批准的单变量对照建议，未实施，也不保证有效。保留奖励、三维状态、7动作、PER及其余参数；不新增人工动作规则。

### 4.3 IS、失败配额和有效梯度的证据边界

普通PER池299790条、失败终止210条；alpha0.6、beta1、epsilon1e-6、每batch固定2条失败终止均正确接入。

普通池`p_i=(|δ_last|+epsilon)^alpha / sum_mass`，`w_i=(N*p_i)^(-beta)/Z`。当前最小p约通过JSON保存，`Z=983.53729`；当前分布期望batch平均IS权重0.00101674。

beta=1时，普通池`p_i*w_i=1/(N*Z)`：IS恢复的是原有固定失败配额下的普通池均匀目标，再以共同常数缩放；不是为hold单独设置小梯度。失败配额样本也使用同一个Z。极小权重本身不能证明Adam参数几乎不动，本轮没有逐更新参数位移记录，不据此断言优化器失效。

使用当前误差计算 `E[w*min(|δ|,1)]` 的类别份额：普通非终止73.19%、失败前缀19.65%、失败终止6.80%、正常终止0.369%。这只是**输出层Huber绝对斜率代理**，不是共享参数梯度、更新方向或Adam步长；没有将代理冒称参数梯度实测。

### Target更新是否滞后或漏执行

`src/v4/dqn.py:486–488`每次Adam.step后计数并执行soft update；`:824–828`执行`target.lerp_(online,tau)`。从续训状态、逐轮CSV和报告核对：初始同步1次、经济更新34807次、软更新34807次；bootstrap468次、正式34339次。没有发现漏更新。

tau0.001的EMA平均年龄约999次更新，半衰期692.80次更新；在replay32下对应约22169.6条新增经验的半衰期，不等于把未来奖励再打折。R90到R100执行3668次更新，R90 Target分量剩约2.5481%。

真实保存的十轮快照中，Target100最接近Online100，而不是Online90：参数RMSE为0.007117 vs 0.017970，219状态7Q MAE为0.069283 vs 0.152432。稀疏快照不支持“Target停留在第90轮”，也不能排除更短时间尺度的跟踪滞后或排序波动。没有证据足以将其认定为主因或立即调整tau。

## 8. 仅推荐一项优先验证：replay32 → replay16

**修改对象是经济Q更新密度，不改DDQN目标、奖励、状态、PER、学习率或tau。** 普通pool每32条新增经验约获得62次抽样机会，即每新增经验约1.94次普通抽取；当前每轮约400次更新、30万条池，局部重要经验更新有限。当前偏差已有方向性，先提高已有正确目标的拟合机会，比同时增加奖励或指定动作更容易解释。

这只是有依据的实验假设，并非“已证明加倍更新会改善”。文献依据是Fedus等(2020)对容量与replay ratio的独立研究；其Atari结果不保证迁移到船舶控制。[论文](https://proceedings.mlr.press/v119/fedus20a.html)。PER原方法也不保证所有状态和动作价值都拟合准确。[Schaul等](https://arxiv.org/abs/1511.05952)。

实施位置（本轮不改）：`src/v4/experiment_schedule.py` 已支持replay16，`monitored_training.py`已传递并记录cadence；`feedback_study.py:78–83`当前冻结检查强制replay32，后续需经批准仅为独立实验身份允许replay16，不能仅传参假装生效。

- 现有100轮为基准；新组从相同seed42的新网络/空Replay/新Adam开始，保持数据SHA、初始条件、探索、PER、batch64、tau0.001、gamma1、n_step1、奖励及预算100轮相同，只改cadence，独立输出。不是续训R100。

- **重要耦合：** 每次Adam后都会soft update，tau固定时加倍更新也会加快Target相对环境经验的跟踪。故该对照检验的是“现有调度下提高更新密度”的整体效果，不能把所有改善独归因样本覆盖。本轮不偷偷修改tau补偿。
- 在相同、预先固定的Train诊断经验上比较未加权各类TD、动作优势误差；Validation020仅做闭环诊断，不参与拟合、优先级调整或动作标签监督。
- 最终必须同时比较固定Train35/Validation8的完成率、物理失败、仅完整且同集合的Zhou成本、SOC范围、FC平均绝对变载/反向次数；不把更短失败轨迹的低费用当改进，不使用Test。
- 若更多更新未改善固定经验残差，或只是改善一类而恶化其他类，或拟合改善但完成率/经济/振荡没有改善，则“更新密度不足是主要可修复原因”的假设不获支持；停止据此继续加更新。需要新的独立证据再决定其他修改。
- 单seed改善只能算初步支持，稳定性需之后经批准的多seed复核。本轮没有启动该实验，也未选定新正式参数。
