# 第100轮DDQN checkpoint只读诊断与反事实分析

日期：2026-10-18。对象为独立航段实验`V4-INDEP35-M3-DELTA7-ZHOU-TD1-PER-S42`，不是合格最佳模型。

## 一、结论摘要

1. **020振荡是真实网络排序，不是状态重建错误或物理mask强迫。** 64/64个执行动作均与真实第100轮权重的贪心选择一致，7档增量和保持动作均合法。
2. **不能只用“小Q差导致抖动”解释。** 最优与次优差值通常较小，但保持动作被系统性排低；反向步骤的最优–次优间隙并不更小。
3. **当前即时奖励没有鼓励这段振荡。** 同一精确物理状态下，64/64步实际动作即时奖励均差于保持。合法150 kW窗口对照完整完成，经济费用与完整训练目标同时改善，证明存在更好控制空间。
4. **015原Greedy进入高负载块时储能已经不足。** 即使从该入口立即切到600 kW、忽略爬升限制，也无法完成整个高负载块。必须更早储能，但本次指定的逐步最大下一SOC干预先在SOC上限处进入增量死端，未形成全航段可行性见证。
5. 优先核查**经济Q拟合/目标一致性**，并独立明确**离散增量可达性**；本轮证据不支持首先再加大波动罚项，也不足以直接确定新状态或新超参数。

## 三、真实Q值与合法动作

由真实轨迹恢复`previous_fc = fc_kw - action_delta_kw`，并核对相邻动作历史。当前及后继mask调用正式`feasible_fc_actions()`和`candidate_fc_actions()`，没有另建近似掩码。

- 020窗口64/64、015前缀155/155动作与真实权重的贪心选择一致。
- 所有当前/后继掩码与原归档一致；015已有5条逐动作Q记录的7个数值与重新前向结果逐值相等。
- 每次推理batch=1，与正式选择时一致，避免批处理GEMM末位差异误判近似并列。

### 020：存在近似并列，但保持动作明显排低

|指标|最优−次优Q|最优−保持Q|
|---|---:|---:|
|最小|0.00000893|0.034524|
|中位数|0.005795|0.050903|

这些Q使用缩放后的训练奖励单位，不是人民币费用。52/64步最优–次优差小于0.01，6/64小于0.001，但最优–保持差始终明显为正。因此主要不是“保持与变载之间随机打平”：网络持续偏好变载，实际为43次−30、21次+60。

反向组40步最优–次优差平均0.007339，非反向组24步为0.004622。不能声称反向动作都由更小间隙造成。没有精确历史权重，不能直接证明该排序对38/62→100轮参数变化的敏感性。

例：第55步SOC0.724692、负载310.5757 kW、上一FC150 kW，实际选择+60至210 kW；Q(actual)=0.097620，Q(hold)=0.032277。保持并非物理不可行，而是被网络排低。

同一第100轮Target与Online在这些状态的最优动作仅13/64一致。这是同快照两网分歧，不证明Target更正确，也不能替代历史敏感性实验。

### 015：失败前风险价值仍有偏差

155步最优–保持差平均0.105975；最后32步平均0.249067，最优Q平均−7.281409。已能看到接近失败时Q明显变负，但这不等于较早的风险和动作差异已正确学习。

本轮10个历史诊断状态中已有记录支持：SOC约0.393、负载约1097、上一FC500时，网络仍将降至470排在保持500及增至560之前。完整7Q及所有实际状态见两份`q_action_audit_*.csv`，不以单一总体TD MAE替代动作排序证据。

### 当前Q偏好与bootstrap目标偏好的分离

进一步使用后文精确的一步actual/hold物理结果，为各候选构造其真实后继SOC和FC状态，再用历史记录的下一时刻负载计算正式掩码和冻结DDQN目标。这只用于离线诊断，不将未来负载提供给在线动作选择。所有64×2个候选后继均存在合法增量，无需虚构失败罚。

|同一64状态的比较|偏好实际变载|偏好hold|
|---|---:|---:|
|当前Online Q|64|0|
|精确即时奖励|0|64|
|冻结1-step DDQN目标|24|40|

平均`Q(actual)−Q(hold)=+0.0518365`，但平均`target(actual)−target(hold)=−0.00628387`，两种动作差相差0.0581204。具体而言，43个−30动作中37个当前目标已经偏好hold；21个+60动作中18个当前目标仍偏好变载。

这区分出两个并存问题：**多数状态的当前动作排序连本快照的一步目标也未拟合一致；另一些状态的bootstrap估计仍支持变载。** 不能只归因即时奖励，也不能把全部问题都归因目标网络。冻结目标本身仍是学习估计，不是长期真实最优价值，见`bootstrap_action_comparison.csv/json`。

## 四、精确单步奖励分解

从正式`AccountState()`，按每个真实已执行动作及实际步长调用`EconomicMPC.interval()`，重建SOC、FC累计电压损失、电池累计weighted-Ah。两样本SOC、账本及奖励分项对档案的误差为0；完整环境重放对账仅有约10⁻¹³量级加法误差。这里复用其正式物理经济接口，没有运行MPC优化器。

在每个同一真实前状态，对实际动作、hold以及合法±60动作单独执行正式一步计算。773行分项结果见`reward_decomposition.csv`。候选计算不推进原始实际路径，不添加虚构失败或终端费用。

正常原始奖励为：

`−[C_H2_actual + C_SOC_equivalent + C_FC_deg + C_Bat_deg + 200(SOC_next−0.6)^2 + 0.0018375*delta_FC^2]`。

实际氢耗＋带符号SOC能量修正合并为等效氢耗，再加FC与电池退化，是经济三成本；SOC及平方变载两项仅用于训练。原始奖励统一乘0.001一次。015的10132.6600879失败惩罚只在实际末transition出现一次，不给候选动作假设尚未发生的失败。

第55步实际+60→210的缩放奖励−0.0206020，hold150为−0.00746129。额外损失主要来自已有FC变载退化及平方波动项，不是SOC项在即时层面鼓励跳变。

015的155步hold同样均合法，150个变载步的即时奖励均差于hold，5个hold步相等。**不能因此把永远保持低FC视为长期最优**：该航段后续有大量供能需求，必须考虑完整后果。

这证明该样本存在更好的合法控制轨迹，不证明150 kW适用于其他航段，也不将其部署为在线控制器。

## 六、反事实B：015提前最大化下一SOC

依照要求，在原最后32步窗口开始前，每步选择正式合法增量中使下一SOC最高的动作；从窗口起点再恢复原Greedy。窗口位置来自原失败结果，是**事后指定的离线信息**，不提供给在线DDQN。

结果没有到达原窗口：执行47步后，在0基row47（第48个控制点）失败。SOC=0.79996199，上一FC600 kW，负载309.35578 kW；物理绝对可行动作为0–310 kW共32档，而7档增量在范围内最低只能到540 kW，无法避免下一步SOC超过上限。因此属于`increment_action_limited`。

**逐步最大化下一SOC并不是全局可达SOC上界。** 高SOC时后续可能缺少降FC空间，该指定干预本身会进入死端。本次据实保留失败，没有自动裁剪、扩大动作或加入降SOC规则来掩盖。

该47步前缀三成本632.64元，原Greedy155步失败前缀为2085.36元；长度和任务结局不同，**不比较经济改善比例**。

### 进一步核查：015是否结构性功率/能量不可行

正式参数为FC上限600 kW、电池624 kWh、SOC范围0.2–0.8，放电上限1248 kW。完整航段最高负载1103.8819 kW，FC600时需要电池503.8819 kW，没有超过电池功率上限。

连续负载超过600的区间为第105–174步，共2100 s。调用正式SOC/效率公式做**乐观必要条件**计算：即使FC立即且全程600，仍需电池内部储能299.06946 kWh，要求区间入口SOC至少0.67927799，尚未考虑增量爬升。原Greedy实际入口SOC=0.67427434、上一FC210 kW；即使忽略爬升也至少缺3.12227 kWh，因此从该实际入口开始无法撑完整个高负载块，后期才增FC已经来不及。

若入口SOC为0.8，这个负载块在立即600的松弛假设下末端SOC约0.320722，**没有发现能量必要条件所能证明的必然不可行**；但该松弛计算不是正式可行轨迹，不证明从独立航段初始条件出发能合法达到此入口SOC及FC。

结论是：需要更早供能已得到必要条件支持；提前保留SOC能否在全部增量与SOC约束下完成整段，**本次未证明**。要关闭这一不确定项，需要单独的离线可行性求解和正式环境见证；本轮没有追加第三种控制策略。

## 七、原因分类及下一步优先级

|问题|本轮证据|结论强度|
|---|---|---|
|错误checkpoint/状态/动作符号|身份匹配、动作219/219复现、掩码一致、已归档Q一致|已排除本次重建错误|
|即时奖励直接鼓励020振荡|64/64步hold即时更优；完整150对照奖励与经济都更好|不支持该解释|
|当前Q排序偏好变载|actual−hold Q平均+0.051837；全部合法保持仍不选择|直接证实|
|Q差小导致所有反向|top2有近似并列，但反向组差反而更大、hold差不小|只能部分支持敏感性假设|
|价值拟合/目标偏差|同快照残差全负、Online与Target最优仅13/64一致|支持价值学习尚不一致；不定位唯一来源|
|状态信息不足|minimal3没有任务阶段/负载上下文；相同三状态可能不同未来|合理假设，尚无本轮因果证明|
|015储能不足|真实高负载入口低于忽略爬升的最低能量要求|已证实当前路径进入后无法补救|
|整个015物理无解|必要条件未排除可行，但指定B提前进入增量死端|本轮未证明|
|增量可达性缺口|B高SOC时绝对动作可行、7档不可达；旧044证据同类|直接证实，不能归于Q误差或总容量|

建议顺序：

1. **首先明确增量动作的任务可达性边界，同时以现有奖励审查Q学习稳定性。** 控制失败应先区分动作集合死端与储能分配。对020，重点是冻结同参数目标下的动作差异拟合、Online/Target偏差和更新干扰，不能仅用小训练Loss或调大学习率代替验证。
2. **随后验证状态歧义。** 通过Train近邻状态的未来回报冲突及受控对照判断是否需要额外在线可观测历史信息。不能加入未来负载、真实剩余航程或验证集事后信息作为在线输入。
3. **暂不优先增加SOC或波动罚。** 现有奖励已经即时惩罚振荡，并允许更平稳且完整奖励更优的020轨迹；再加罚无法解释当前Q为何不选择它。是否更换DQN/DDQN、gamma、学习率等，须另行受控证据，本轮不实施。
