# V6 正式8轮训练：控制表现与失效分析

正式 run02 已完成8轮，但 Greedy Validation 没有稳定改善，第8轮仅完成3/8。第2轮出现过较平稳的7/8控制，随后完成率和FC波动反复恶化。已有证据不支持“8轮后已经收敛”或“最终 checkpoint 最优”的结论。

本报告只分析已保存的 Train/Validation 报告、指标、轨迹与源码；未启动新训练、仿真、反事实实验或测试，未读取 Test。Train 含随机探索，其完成率不能替代 Greedy Validation 性能。正式配置为普通 DQN、单步TD、学习率0.0001、SOC权重0.2、FC波动权重0.05；13档动作对应每1秒实际FC增量 −60～+60kW，间距10kW。最大增量是仿真假设，不能表述为已标定实船FC爬坡能力。

汇总数据见 [round_metrics.csv](browser/round_metrics.csv)，逐航段数据见 [validation_all_voyages.csv](browser/validation_all_voyages.csv)，原始总报告见 [raw/run02/report.json](raw/run02/report.json)。

## 时序与解释限制

失败F秒是下一次决策发现没有合法动作的时刻。轨迹最后实际执行行通常为F−1秒，该动作推进SOC后，下一状态无合法动作，因此该行附失败终止标记和一次失败惩罚。不能在F秒再补造一个“已执行动作”，也不能把F−1行的 `soc_before` 与F时SOC混为同一时刻。

这里只确认已有行为轨迹中的失效和性能变化，没有用“未发现错误”证明整个实现正确。报告也不能凭控制失败认定网络没有训练；梯度、参数及Q拟合证据需要与本报告共同阅读。TD目标是当前自举学习目标，拟合改善不等于最优策略，更不等于Greedy控制已经改善。

## 下一版优先处理的两项

1. **先补与现有增量约束一致的可恢复性检查。** 在 `src/v4/control.py` 的 `_v6_feasible_fc_actions` / `replay_episode` 物理合法动作链中，研究候选动作执行后是否会使下一状态失去可达合法动作，避免只检查当前1秒SOC。遇到负载预测误差时，应明确保证条件；本次证据不能支持无条件安全承诺。若扩大动作最大增量，必须作为新的仿真假设独立记录，不能冒充实船爬坡标定。只增加档位密度不能解决第8轮这五条范围不足。
2. **以低SOC失败前动作排名和失败代价拟合为价值学习的首要验收项。** 对照保存的全13动作Q值、真实Train失败终止/前缀误差以及各checkpoint的Greedy控制，定位016低SOC降FC、033/044/045低SOC保持低FC的价值排序问题；不能依据普通样本Loss或更新次数选最终轮。`src/v4/v6_q_probes.py`、`v6_td_diagnostics.py` 和 `v6_train_values.py` 已保留这类证据，应先用现有资料确定最小修正，再决定下一次训练。不要把当前现象直接归因为“只需更多轮次”，也不需要据此展开PER、Dueling或全动作监督实验。

以上均为下一版建议，本次未实施算法、奖励、动作空间或训练预算修改。
