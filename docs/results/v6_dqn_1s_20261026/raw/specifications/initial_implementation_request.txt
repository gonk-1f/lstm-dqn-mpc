## 三、数据集修改：原有数据插值到1秒

### 3.1 最重要的要求

**插值仅用于在现有相邻数据点之间增加新的时间点，不允许改变原有任何时间点的负载功率值。**

假设现有航段具有：

| 时间 | 负载 |
|---|---|
| 0秒 | 200 kW |
| 30秒 | 500 kW |
| 60秒 | 400 kW |

插值后必须保持：

- t=0秒，负载仍为200 kW；
- t=30秒，负载仍为500 kW；
- t=60秒，负载仍为400 kW。

只在0～30秒、30～60秒的内部增加每秒负载值。

优先使用分段线性插值，保证：

1. 所有原始时间戳及对应负载功率完全保留；
2. 新增点来自相邻现有锚点之间的线性插值；
3. 不采用会改变锚点或额外产生超调的平滑处理；
4. 不重新执行原始船舶数据清洗、裁剪、航段划分或PCHIP重建；
5. 不改变航段起点、终点、原有负载峰值及已确定的工况边界；
6. 不跨越不同航段、unknown区域或已有数据断点插值；
7. 如果现有航段已经是1秒数据，则原样复用，不重复插值；
8. 其他分类字段按原字段语义处理，不对岸电标志等离散标签进行数值线性插值。

必须直接使用当前已生成的训练集，而不是回到最早上传的原始遥测数据重新划分。

## 四、V6强化学习算法

### 4.1 标准DQN

将现有DDQN改为普通DQN：

- 保留Online Q网络；
- 保留Target Q网络；
- 不再使用Double DQN的Online选动作、Target评估动作机制；
- 不使用Dueling；
- 不使用全动作监督；
- 保持单步TD。

目标公式：

`y = r + gamma * (1-done) * max_legal Q_target(s_next, a)`

正常终止和失败终止均不bootstrap。

下一状态选择最大Q时必须使用实际合法动作掩码。

每条Replay经验仅监督实际执行的动作。

### 4.2 网络

结构：

`5 → 256 → 256 → 13`

- 隐层ReLU；
- 输出层Linear；
- 13个输出对应13个动作；
- 不对Q值施加人为限制；
- 输入状态执行既定归一化。

采用新初始化的Online与Target网络，不从旧4维、7动作的checkpoint续训。

### 4.3 学习参数

- Optimizer：Adam；
- Learning rate：0.001；
- Adam betas：(0.9,0.999)；
- Adam eps：1e-8；
- Loss：SmoothL1/Huber；
- Huber beta：1；
- Gradient clipping：最大范数10；
- Gamma：1.0；
- n-step：1；
- Reward scale：1，不再乘0.001。

不得未经要求将学习率改为0.0001或更换损失函数。

## 五、五维状态空间

统一输入顺序：

1. 当前SOC；
2. 当前负载/600；
3. 上一实际执行时刻的FC功率/600；
4. 当前负载与30秒前负载之差/600；
5. 最近300秒历史负载均值/600。

公式：

`s = [SOC_t, Pload_t/600, PFC_previous/600, (Pload_t-Pload_t-30s)/600, mean(Pload_history_300s)/600]`

注意：

- 30秒差分指真实时间窗口，不是30秒控制周期；
- 300秒历史均值包括当前及过去可观测负载；
- 不得使用未来负载；
- 航段开始时按已有历史前缀构造窗口；
- 每条航段开始时清空历史缓存；
- 不裁剪超过1的负载归一化值；
- SOC输入本身保持0～1，不使用奖励中的0.1分母修改状态。

当前状态与下一状态必须使用相同的状态定义。

## 六、动作空间：13档，每秒直接执行

动作集合：

`[-60,-50,-40,-30,-20,-10,0,10,20,30,40,50,60] kW`

**这些值代表每一个1秒决策周期的实际FC功率增量。**

正确执行：

`PFC_next = PFC_previous + action_kw`

禁止使用：

`action_kw / 30`

也不采用所谓的30秒等效指令。

例如，当前FC为200 kW，选择+30 kW，则本次执行目标是230 kW。

实际物理约束：

- 聚合FC额定功率0～600 kW；
- 电池功率约束使用现有模型；
- SOC硬约束继续使用0.2～0.8；
- 按实际执行后的功率检查合法性；
- 不允许静默裁剪动作来伪造可行控制。

±60 kW/s目前定义为仿真动作能力假设，未取得实船动态响应标定，不得宣称是已经核实的硬件爬坡能力。

要保证行为策略、合法掩码、环境执行、Replay记录和Target计算中的13档索引完全一致。

## 七、奖励函数

V6上层训练只使用：

1. 燃料电池氢耗费用；
2. 锂电池等效氢耗费用；
3. SOC维持惩罚；
4. 燃料电池总功率波动惩罚。

奖励定义：

`r = -(C_fc_h2 + C_bat_h2eq + C_soc + C_fc_ramp) - failure_penalty_if_terminal`

其中：

`C_soc = 0.1 * ((SOC_next - 0.5)/0.1)^2`

`C_fc_ramp = 0.1 * (PFC_next - PFC_previous)^2 / 600`

这两个0.1是本版工程初始权重，不得自行改变。

要求：

- SOC目标固定0.5；
- SOC分母固定0.1；
- SOC采用平方偏差；
- FC波动采用实际1秒FC增量的平方；
- 波动项分母固定600；
- 不使用奖励缩放系数；
- 氢耗及电池等效氢耗按真实执行的1秒积分；
- 保留原电池等效氢耗符号和效率模型；
- 失败惩罚沿用现有一次性终止惩罚；
- 不将FC退化和电池退化费用直接放入训练奖励。

同时，**必须保留原四项经济账本**，在Validation阶段报告氢耗、FC退化、电池退化和总经济成本，以判断平稳性改善是否真的降低实际费用。

奖励各分项需分别记录原始值与累计值，不能将训练辅助惩罚当作真实经济支出。
