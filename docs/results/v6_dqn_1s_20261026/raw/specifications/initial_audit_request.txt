## 三、必须考虑的既有问题

以下是已有研究中反复出现的问题，请检查实际代码和已有证据是否支持这些结论。

### 3.1 Q网络动作排序错误

历史诊断已经观察到：

- 实际变载动作的即时经济奖励经常差于保持动作。
- 部分状态下，Online Q网络仍然偏好变载，而现有TD参考目标更偏好保持。
- 某些动作的Q优势随网络参数更新顺序发生明显漂移。
- 固定目标的副本拟合实验出现过终止样本与非终止样本误差相互恶化的情况。
- Dueling结构没有解决FC频繁变载，Uniform采样也没有稳定解决变载与经济成本问题。

请重点检查：

1. 当前Online网络与Target网络的实际计算逻辑是否正确。
2. 动作索引、动作数、功率增量映射、合法动作掩码、Greedy选择及TD目标中的动作选择是否完全一致。
3. 当前网络是否只对Replay中实际执行的动作建立TD监督，导致未执行动作的相对Q值缺少直接约束。
4. 网络共享参数、Replay样本分布、Target滞后、优化器更新和Q值过估计，分别有哪些已有证据支持其为问题。
5. 普通DQN是否可能加剧过估计；它是否仍然适合当前任务。
6. 现有代码中是否存在真正的动作排序实现错误，还是算法目标正确但学习结果不佳。

必须区分“已确认的代码错误”“有证据支持的算法局限”和“尚未证明的推测”。不能把三者混为一谈。

本轮不实施全动作监督，也不以增加全动作监督作为默认解决方案。

### 3.2 长期价值估计不足与提前耗尽电池

已观察到部分航段在SOC下降到下限附近后，即使燃料电池已经达到较高功率，也可能无法满足后续负载；部分失败状态即使FC在0～600 kW范围内连续调整也无法恢复。

请重点检查：

1. 状态是否足以区分当前负载相同、但后续负载风险不同的情形。
2. 当前负载及其历史统计量是否仅提供过去信息，是否存在未来信息泄漏。
3. 当前状态是否包含足以表示航段剩余时间或终止条件的信息。
4. 如果训练集是已知的完整航段，当前控制器是否实际上只观察当前及过去负载，而没有未来负载计划；这一限制对长期价值学习有何影响。
5. SOC更新是否使用了正确的功率方向、效率、时间步长和电池容量。
6. SOC失败是否主要源于策略未能提前储备能量、当前动作集合限制、真实供电能力不足，还是实现错误。
7. 单步TD、γ=1、有限航段终止和Target更新机制之间是否存在逻辑问题。

不得因为最终SOC不可行就一律归因于物理能力不足，也不得因为提前耗尽电池就一律归因于Q网络。

### 3.3 燃料电池频繁变载与高昂成本

重点检查：

- 保持动作与变载动作的实际即时成本是否计算一致。
- FC氢耗是否依据正确的功率和时间计算。
- FC功率变化是否按真实相邻控制时刻计算。
- 1秒控制下，波动惩罚是否会因为时间步长改变而发生意外放大或缩小。
- 动作是否因量化分辨率、浮点处理、执行映射或合法动作约束而产生不必要的正反向切换。
- 奖励中FC变载惩罚与氢耗成本是否处于合理数量级。
- 当前模型是否把频繁变载视为有利的未来价值来源，尽管其即时经济成本较高。
- 是否存在SOC奖励、失败惩罚或其他奖励项间接促使FC频繁变载的机制。

不要直接建议无限增加波动惩罚。首先检查既有奖励设计和价值估计之间是否存在矛盾。

### 3.4 SOC经常抵达上下限与航段不可行

检查：

- SOC硬约束和软惩罚是否被正确区分。
- 动作掩码是否基于执行后真实可行性计算。
- 当前动作合法不代表下一步必然存在合法动作，代码是否正确处理这种情况。
- 失败终止是否只处罚一次，是否正确停止bootstrap。
- 正常终止与失败终止是否使用一致、正确的终止语义。
- 当前SOC目标、SOC软惩罚与电池等效氢耗是否可能产生相互冲突的激励。
- 电池功率约束与624 kWh能量容量是否被错误地混为一谈。

## 四、V6拟定配置：请逐项审查，不要默认正确

### 4.1 算法与网络

- 普通DQN，不使用DDQN。
- 不使用Dueling。
- 不使用全动作监督。
- 单步TD。
- 折扣因子 γ=1.0。
- 网络结构：5–256–256–13。
- 隐藏层使用ReLU，输出层为13个线性Q值。
- 优化器Adam。
- 学习率0.001。
- Huber损失，beta=1。
- 梯度范数裁剪10。

请判断普通DQN在当前问题下是否可行，特别检查去掉Double DQN后是否存在更严重的过估计风险，以及学习率0.001与无奖励缩放、单步TD和硬Target更新组合时是否合理。

如果存在明确冲突，请说明数学或代码依据，并给出下一阶段应采用的具体修改建议，而不是要求再做多组实验。

### 4.2 状态空间

拟定5维状态：

1. 当前SOC；
2. 当前负载 \(P_{\mathrm{load},t}/600\)；
3. 上一时刻FC功率 \(P_{\mathrm{FC},t-1}/600\)；
4. 过去30秒负载变化：

\[
\frac{P_{\mathrm{load},t}-P_{\mathrm{load},t-30s}}{600}
\]

5. 截至当前时刻、最近300秒负载均值：

\[
\frac{\overline P_{\mathrm{load},t-300s:t}}{600}
\]

检查实际状态构造代码是否与以上定义完全一致，尤其是历史窗口的时间单位、航段起始边界、归一化和历史缓存。

判断这5维是否能够表达当前控制问题所需的状态信息；如仍有不可观测的未来负载信息，明确指出DQN无法直接知道哪些信息。

### 4.3 13档动作空间与1秒执行

拟定13个30秒等效功率增量：

\[
A=\{-60,-50,-40,-30,-20,-10,0,10,20,30,40,50,60\}\ \mathrm{kW}
\]

在1秒控制步长下，实际执行增量为：

\[
\Delta P_{\mathrm{FC},t}=\frac{a_t}{30}
\]

即每秒实际功率变化范围为±2 kW，动作档位间隔约0.333 kW。

请检查：

1. 当前环境能否准确实现这一映射。
2. FC功率范围0～600 kW及动作合法掩码是否与13档动作严格一致。
3. 该功率分辨率是否具有实际意义，是否会导致大量动作的价值近似并列。
4. 1秒步长下的动作幅度、执行周期和物理设备限制是否一致。
5. 原有30秒数据插值为1秒后，是否有必要将其视为真正的1秒在线控制。

不能擅自把±2 kW/s扩大成±60 kW/s，也不能将未经设备标定的爬坡率说成实船参数。

### 4.4 奖励函数

拟定奖励：

\[
\begin{aligned}
r_t=-\bigg[&
C_{\mathrm{FC,H2},t}
+C_{\mathrm{Bat,H2eq},t}\\
&+\lambda_{\mathrm{SOC}}
\left(\frac{SOC_{t+1}-0.5}{0.1}\right)^2\\
&+\lambda_{\Delta P}
\frac{(P_{\mathrm{FC},t}-P_{\mathrm{FC},t-1})^2}{600}
\bigg]-C_{\mathrm{fail},t}
\end{aligned}
\]

配置意图：

- FC氢耗；
- 锂电池等效氢耗；
- SOC目标0.5，归一化分母0.1；
- FC波动使用平方惩罚，分母600；
- 不显式把FC与电池退化成本加入训练奖励，但继续在经济评价中计算；
- 不乘0.001等奖励缩放系数；
- 失败惩罚只在真实失败终止时计入一次；
- 初步工程权重：SOC权重1.0，FC波动权重4.0。

请特别审查：

1. 氢耗和电池等效氢耗是否真的是每1秒的费用，而不是原30秒费用。
2. SOC权重1.0与平方偏差的组合，是否可能使SOC惩罚远大于真实单步能源成本。
3. 波动项 \((\Delta P)^2/600\) 的单位、数值尺度和权重4.0是否合理。
4. 奖励不缩放时，Huber beta=1、学习率0.001和失败惩罚是否可能造成过大的TD误差或梯度。
5. 当前SOC惩罚和FC波动惩罚是否存在目标冲突。
6. 删除显式退化成本后，是否仍能通过经济评价识别FC频繁变载的实际退化代价。

请明确给出奖励各项的量纲、数量级问题和必须修改的公式或权重。不要为了符合既定配置而忽略明显的数值错误。

### 4.5 Replay与训练机制

拟定配置：

- 纯Uniform Replay。
- 不使用PER。
- 不使用失败终止固定配额。
- Replay容量1,000,000。
- Batch size 64。
- Replay预热50,000条经验。
- 每个1秒环境步执行1次Adam更新。
- 每次只执行1次梯度更新。
- Target硬更新，每累计1000次Adam更新完整复制一次Online网络。
- Target更新计数跨航段累计，不在航段结束时重置。
- epsilon从1.0线性下降到0.05，前6次完整Train遍历衰减，最后2轮保持0.05。
- 训练预算8次完整Train遍历。
- Validation每完成一次完整Train遍历进行一次。
- Test完全封存。

请检查当前源码是否容易把环境步、梯度更新次数、Target更新计数和训练轮次混为一谈。

重点判断：

1. 1000次Adam更新的硬Target复制间隔在每秒更新机制下是否合理。
2. 1,000,000容量、50,000预热和约458,000步/完整Train遍历是否存在明显冲突。
3. 训练8轮时，FIFO Replay是否会淘汰大量早期航段经验。
4. epsilon按训练轮衰减还是按环境步衰减，是否与实际训练进度一致。
5. 纯Uniform且没有失败配额后，失败终止经验是否可能过度稀少。
6. 学习率0.001、每步更新、Huber beta=1和硬Target复制周期1000的组合是否存在已知的稳定性风险。

请注意：1秒插值并没有创造30倍独立实船信息。不要把环境步数量增加等同于数据的信息量增加。
