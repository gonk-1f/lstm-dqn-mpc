## 4. 物理方程、掩码与索引核对

正式参数：E=624 kWh，η充=η放=0.95，SOC∈[0.2,0.8]，母线电池功率∈[−624,1248] kW。Pbat=L−Pfc，Pbat>0为放电；SOCnext=SOC−Pcell×dt/(3600E)，其中放电Pcell=Pbat/η放，充电Pcell=η充×Pbat。

对dt=1秒，Bmin=max(−624,−(0.8−SOC)×624×3600/0.95)，Bmax=min(1248,(SOC−0.2)×624×0.95×3600)。连续FC区间为[max(0,L−Bmax), min(600,L−Bmin)]。本报告按此反解得到的10 kW网格边界与8条失败记录一致。

未发现所查链路存在SOC上下限反号、电池充放电方向错误、遗漏1/3600、误用30秒、增量除30、掩码与实际执行不一致或前后时间错位。代码位置：src/v2/config.py:87；src/v2/models/battery_energy.py:91；src/v3/control.py:38、144；src/v4/actions.py:11、48；src/v4/control.py:377、530、543、558、578、667、687。

002最后轨迹行t=10086执行FC310，把SOC从0.799830938推到0.799944347；在t=10087、负载42.163803时，FC连续上界173.762534，下一增量最低250，因此报错。016最后行t=7214执行FC100，把SOC从0.200223474降到0.200000782；在t=7215、负载574.458292时，FC连续下界572.789282，而下一增量最高160。报错晚于最后执行行1秒符合时间语义。

明确的控制设计缺口是：当前mask只保证本1秒结束合法，没有保证所选动作后的状态仍能按±60 kW调整而恢复；下一步mask是在动作执行后才计算。失败终止和一次惩罚会在事后记录，但不会事前排除这样的动作。源码按当前冻结设计执行，这不是SOC积分实现错误。

本次依据的是实际V6实现。其DirectPowerDQN.learn位于src/v4/dqn.py:1164，目标复制在1185，未调用旧类的soft_update_target；不能把旧实现的软硬混合问题归到该V6运行上。

## 5. 提前决策是否可能避免

8条在F−60都有局部提前调节空间：7条高SOC病例尚有约2.82～6.86 kWh的电芯充电余量；016尚有约7.45 kWh的电芯放电余量。0～600 kW跨完整范围最多需要10次±60 kW调整，而10秒按电池额定上限累计的最大电芯充电量仅1.65 kWh、最大放电量3.65 kWh。结合这60秒的已观测负载和完整0～600可行区间，约束不支持“60秒前就已无解”；更早减充或增加FC存在明确局部可能。此为功率和能量上界的代数核算，没有生成任何替代轨迹，不保证换动作后能完成整个航段。

逐条：002、011、020应更早降低持续过量FC；033应在负载下降和SOC上涨时降低FC，而不是末秒增加；040、044、045需将已经发生的减载提前，不能等待保持动作被当前mask排除；016需在SOC下探期间提高FC，避免继续扩大电池放电缺口。不能把“失败前一秒换一个动作”当成8条通用修复，部分病例到该时刻已经太迟。
