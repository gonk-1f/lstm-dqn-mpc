# V4 已观测前缀回放修复与诊断

## 范围与依据

本轮执行用户确认的最小改进路径。修复 UNKNOWN 前完整已观测窗口被整段丢弃的问题，并增加真实采样/正常终止 TD 统计。保留原奖励、7维状态、61动作、物理mask、失败惩罚、配额2、replay32和软更新参数。不添加人工动作门控、强制FC出力、平滑奖励、PER或新的预测输入。正常样本的终止定义暂不改动。

- [Double DQN 原论文](https://arxiv.org/html/1509.06461v3)：在线网络选择后继动作，目标网络估值。保留当前算法。
- [Rainbow，第2.3节](https://arxiv.org/pdf/1710.02298)：已执行多步奖励与后继价值构成 n-step 目标；本轮不改变既有 n=8 或其行为策略回报处理。
- [Pardo 等，Time Limits in Reinforcement Learning，第3节](https://arxiv.org/pdf/1712.00378)：区分任务真正终止和数据采集截断。其理论支持不能将截断当作零后续价值；本项目 UNKNOWN 的后继观测缺失，因此更保守地仅使用缺口之前已观测完整窗口，不能在缺口处虚构后继或bootstrap。

这是上述 Bellman/n-step 机制在数据缺口边界的工程应用，不声称论文直接研究了本船UNKNOWN标签，也不保证完成率因此提高。

## 实施计划

1. 在现有测试中先构造 UNKNOWN 短/长前缀、真实后继和岸电边界；确认修复前缺少有效前缀插入路径。
2. `dqn.remember_observed_prefix` 只插入完整 n-step 奖励且窗口后真实下一决策已执行的非终止经验。若前缀有 L 个决策，起点 i 必须满足 `i+n<L`。真正闭合的独立段仍按原终止规则处理；未闭合窗口标记 `unresolved`，不得计作成功或失败。
3. 正式入口提供 `observed_nstep` 与 `discard` 对照开关，默认启用前者。真实物理失败仍沿用现有一次性惩罚和失败终止经验。新增插入数如实计入原 replay32 credit，不改更新比例。
4. 在不改变随机抽样或TD公式的前提下，记录正常终止/失败前缀/未知结果经验的真实采样及TD统计、SOC/负载/动作覆盖，以及少量关键来源记录在当前Online/Target快照下的目标。来源信息只用于诊断，不能进入策略状态。
5. 保存/恢复新增计数与来源，版本化Replay契约；不允许用旧训练checkpoint跨新契约续训。使用少量合成定向检查确认边界、缩放、失败与诊断RNG隔离。

## 不处理的未决问题

文件末端是否代表完整有限任务，仍缺业务依据；不把它机械改为非终止，也不添加真实剩余长度。共同拟合干扰、状态混淆、采样改进和FC平稳性须分别做经批准的受控实验，本轮不修改对应机制，不开展正式训练。

## 验证结果

本轮仅使用合成边界检查，没有读取正式 Train/Validation/Test 轨迹，没有正式训练或修改历史输出。

- 新前缀及诊断测试先观察到8项失败（缺少原接口），实现后全部通过。
- 根进程运行38项定向检查通过：前缀短/长窗口、岸电连续性、正常闭合段、折扣与一次缩放、原失败终止/n-step配额、FIFO、诊断开关RNG及网络结果一致、软Target更新、完整轮次恢复。
- 入口接线另运行13项定向检查通过：默认/旧模式显式传递、真实源行、UNKNOWN与物理失败独立计数、Validation独立执行、资格筛选、旧Replay契约拒绝、既有确定性与异常退出。合计51项；未运行全量测试。
- 合成52个已执行ONBOARD决策，含真实模型SHORE边界：每次插入44个完整n8窗口，舍弃8个尾窗。预填充加一次合成轮次共88个新经验，replay32信用与实际插入一致；`discard` 对照插入0个。UNKNOWN成功/物理失败/正常终止计数均为0，经济评价资格不变。
- 独立审查未发现必须修复的Bellman或采样边界错误；来源只用于诊断，原 `random.sample/shuffle` 调用顺序不变。

## 修改位置与新诊断

| 文件 | 变化 |
|---|---|
| `src/v4/dqn.py` | `remember_observed_prefix`、非终止 `unresolved` outcome、来源/Replay ID、正常终止及其他类别TD统计、轻量覆盖计数、有限关键记录当前目标复算、格式2保存恢复 |
| `src/v4/monitored_training.py` | 预填充/训练统一接线；真实原始行来源；UNKNOWN保留/舍弃累计包括预填充；正常/失败/未知结果分别统计；原资格与Greedy只读保持 |
| `src/v4/feedback_study.py` | `--unknown-replay-mode observed_nstep` 默认；`discard` 复现旧逻辑，其他冻结参数不变 |
| 三个直接相关测试文件 | 合成边界、来源、诊断隔离及入口检查 |
| `docs/v4_mode_labels_v3.md` | 修正过时的 UNKNOWN Replay/30/30资格描述，不修改标签 |

`td_statistics.normal_terminal` 明确统计 n-step 终止窗口的真实采样数、Q/目标均值、TD MAE及原单位换算、超过Huber转折点1的占比。`nonterminal_categories` 分开报告普通、失败前缀、未知结果前缀。

`replay_coverage` 报告当前池与本轮真实抽取的SOC区间、负载区间、动作、源样本及采集轮次。分箱仅用于统计，不用于奖励、动作选择或约束；每次插入/抽样增量维护，不逐更新扫描30万条记录。

`watched_replay_targets` 最多保存 `_015`行97、`_005`行208、`_006`行350各最近3条实际来源记录。按同一Replay ID提供累计实际抽取数及当前Online/Target快照下Q、重新计算的y与误差；不存在记录则空缺，不生成经验。它们只是本次诊断的固定观测点，不是策略规则，不改变采样概率。正常终止窗口数量不是独立任务结束次数；关键目标并非历史存储的固定标签，必须按ID与optimizer计数比较。

## 使用与下一步

正式入口默认启用已观测窗口保留；公平对照可显式使用 `--unknown-replay-mode discard`。该选项仅切换未闭合前缀处理，其他学习设置不改。来源和计数随checkpoint保存，经济Replay契约版本为2；旧100轮checkpoint保持原样、不能用于新任务续训，需从新初始化及独立输出目录开始。

本次实现解决的是确定的训练覆盖损失，并提供区分目标漂移/采样稀疏/拟合干扰的证据。它没有验证闭环完成率改善。后续应只比较这一个变化因素，记录新增有效经验与原replay32自然增加的更新次数；如果目标类别改善而普通/失败前缀恶化，不能判为成功，再依据真实计数讨论采样或状态问题。
