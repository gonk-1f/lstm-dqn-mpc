## 为什么是48个候选

原43个样本，_029、_009、_010、_019各拆两段，增加4条。另发现_046除开头UNKNOWN外还有内部UNKNOWN，按照相同原则将其前后有效部分分开，增加1条。因此为43+4+1=48，而不是自动切出几百个片段。

所有48个候选的原v3保留30秒标签中均无UNKNOWN和SHORE。**没有把UNKNOWN改名，也没有跨UNKNOWN连接轨迹。** 只排除了对应区间。046两段应在后续独立SOC初始化；第一段保留其原有长待机形态供人工审查，没有另设低速/低负载阈值自动再切。

## 长时间看似0kW的核对

现用43个1秒文件共86个精确0点，全部位于各文件首尾；内部精确0点为0。当前30秒网格共有2363个非零但绝对值<=1kW的点，其中2086个是[-1,0)kW的小负值。

因此，很多图上的“长时间0”实际上是-0.12、-0.09kW等近零值在大纵轴上显示成平线。现有物理入口的 `normalize_onboard_load_kw()` 又会把[-1,0)数值映射为0；这与原数据中存在一大段严格0是两回事。本轮未改该正式代码，也未把小负值悄悄归零。

旧首尾86个0是既有处理结果，不代表86个原始精确零观测。上一轮已保存的来源审计显示43个来自原始近零快照归零、24个来自样条补点归零、19个来自构造过零。本轮按你的要求保留现用曲线，未再以这些发现重建整套数据。

## 非零边界与审查类别

按**现成处理曲线**的端点容差作审查描述：37条A（首尾绝对值<=1kW）、11条B（至少一个非零边界）、0条仍含UNKNOWN/SHORE的候选。这里A不表示重新验证过真实零边界或全部物理可行。

不能为了符合零边界要求，将_017的56.743kW、_010第二段125.223kW等改成0。B类保留供人工决定；若无法接受途中截取的边界，可以不选，而不能造零。小幅负值也保留原值，后续正式物理输入口径须明确。
